# 数据库说明

## 一、用的是什么数据库

**SQLite**，单文件：项目根目录的 `app.db`。

- **没有用户名和密码**——SQLite 是嵌入式文件数据库，不是服务，谁能读这个文件谁就能访问。
- 后端通过 Python 标准库 `sqlite3` 直连（见 `backend/db.py`），没有 ORM。
- 首次启动服务时自动建表（幂等），并做轻量迁移（如老库补 `wake_time` 列）。

直接查看：

```bash
sqlite3 app.db ".tables"                 # 列出所有表
sqlite3 -header -column app.db "SELECT * FROM users"
```

所有 `*_json` 字段落库时都用 `ensure_ascii=False`，中文可直接读。

## 二、各表用途

### users — 账号
| 字段 | 说明 |
|---|---|
| id | 用户 id，自增 |
| username | 用户名，唯一 |
| password_hash | `盐$SHA256(盐+密码)`，明文密码不落库 |
| created_at | 注册时间（虚拟时钟） |

### sessions — 登录态
最简单的 token 表。登录/注册发一个随机 token，前端每次请求带 `Authorization: Bearer <token>`，后端查这张表换 user_id。没有过期机制（第一版从简）。

### profiles — 用户档案（onboarding 填的）
一人一行，`user_id` 主键。字段：下班时间范围（off_work_start/end）、加班频率、通勤分钟、上班身体状态（久坐/站着走动/体力消耗）、能否做饭、饮食禁忌（逗号分隔，**硬约束**）、健康备注、**起床时间 wake_time**（倒推"几点停"用）、运动基础、性别/年龄/身高/体重（全可空；缺任一项则 `calc_body_metrics` 返回不可用，Agent 就不引用数字）。「我的资料」页改的就是这张表。

### daily_records — 每日建议记录（核心表）
**一天的条件和结果绑在同一行**（将来才能分析"这人在什么条件下会崩"）：

| 字段 | 说明 |
|---|---|
| vday | 虚拟日期，如 `2026-08-13`（全系统的"今天"以虚拟时钟为准） |
| conditions_json | 当天条件快照：来源（onboarding首夜/offwork）、档位、累计的一击纠正列表、Agent 提取的条件 |
| advice_json | Agent 给的建议原文（judgement/reason/eat/move/stop/sources/safety_flag） |
| status | `pending_feedback`（待回执）/ `done`（已回执） |
| feedback | 完成了 / 只完成一部分 / 完全没完成 / 建议仍然太难 / 跳过 / 未响应（连续没打开时系统标的）/ NULL |
| baseline_level | 当天档位 0–4（次日档位由本行的 feedback 按 7.4 规则推出） |

同一天重跑（一击纠正/自由输入/改回执）是**更新同一行**，不新增。

### meal_records — 饮食记录
| 字段 | 说明 |
|---|---|
| vday / vtime | 虚拟日期和时间 |
| source | `photo`（拍照识别）/ `text`（文字，预留） |
| food_json | `{名称, 估计分量, 类别, 备注}`，视觉模型 qwen-vl-max 的识别结果 |
| image_path | 原图路径（`data/uploads/`），删除记录时一并删文件 |

### free_inputs — 自由输入
用户原话（text）+ Agent 用 `log_note` 工具提取的关键条件（extracted_json）。原话和推断分开存。

### user_notes — 长期备注（长期记忆层）
用户的持久习惯/偏好（如"睡前喝一杯热牛奶"），由 Agent 的 `log_note(durable=true)` 工具在对话中自动提取写入，完全相同的内容不重复存。**每次生成建议都全量注入【长期备注】，永不过期**——与 daily_records 的 3 天短期窗口相对。删除某条用 SQL 直接删即可。

### corpus_chunks — RAG 语料块
`doc_name`（手册名）、`category`（diet/exercise/stretch/sleep）、`chunk_text`（300–500 字文本块）。**向量不在库里**，存 `data/corpus.npz`，行号 = id - 1 一一对应。由 `scripts/build_corpus.py` 生成，重跑先清空。

### app_clock — 全局虚拟时钟
只有一行（id=1），`virtual_now` 是 ISO 字符串。全后端业务逻辑禁止用系统时间，一律走 `clock.now()` 读这张表。演示控制条的 +1小时/下一天/重置 改的就是它。

## 三、常用排查查询

```bash
# 某用户最近几天的档位与反馈变化
sqlite3 -header -column app.db "SELECT vday, status, feedback, baseline_level \
  FROM daily_records WHERE user_id=7 ORDER BY vday"

# 今天（虚拟日）都记了什么吃的
sqlite3 app.db "SELECT vtime, food_json FROM meal_records WHERE vday='2026-08-13'"

# 当前虚拟时间
sqlite3 app.db "SELECT virtual_now FROM app_clock"
```
