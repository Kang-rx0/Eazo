# 技术架构说明

> 对应实现文档：`最低自我照顾Agent-技术实现文档-V1.md`。本文写"现在实际是怎么跑的"。

## 一、总览

```
浏览器（frontend/ 静态页，原生 JS）
   │  fetch，同源 /api/*，登录态 = Bearer token
   ▼
FastAPI 单进程（backend/main.py，端口 8100）
   ├─ 代码分流（不用模型做 router）：注册/登录、onboarding、下班了、回执、
   │   一击纠正、自由输入、拍照、改资料、删记录、虚拟时钟、agent_trace
   ├─ agent.py   核心 Agent 主循环（唯一的"智能"入口）
   │    ├─ llm.py    模型调用封装：chat=qwen-plus / vision=qwen-vl-max /
   │    │            embed=text-embedding-v4（百炼 OpenAI 兼容，30s 超时+1次重试）
   │    ├─ tools.py  4 个工具（见下）
   │    └─ rag.py    参考手册检索
   ├─ clock.py   虚拟时钟（全后端禁用系统时间）
   └─ db.py      SQLite（app.db）
```

**不用任何 Agent 框架**（无 LangChain/LlamaIndex/向量数据库），运行时依赖只有 `fastapi uvicorn openai numpy python-dotenv python-multipart`。

## 二、Agent 设计

### 2.1 单 Agent + 工具调用循环

一个主 Agent，OpenAI 格式 function calling，自己写的 while 循环（`agent.py`）：

```
组装上下文（档案 + 近3天记录 + 今天已知 + 虚拟时间 + 当前档位）
循环（最多 6 轮）:
    调 qwen-plus（带 4 个工具定义）
    模型要调工具 → 执行 → 结果塞回对话 → 下一轮
    模型给最终输出 → 校验 JSON（judgement 和 stop 必须在）→ 退出
    JSON 不合法 → 提示重输，重试 1 次
超过 6 轮 → 去掉工具再调一次，强制给结论
任何一步彻底失败 → 返回写死的兜底建议（演示不死）
```

每次运行完整过程落盘 `logs/trace/`（见《日志说明》）。

### 2.2 四个工具（tools.py）

| 工具 | 作用 | 说明 |
|---|---|---|
| `search_reference(query, category)` | 查参考手册 | 返回 top-3 文本块+来源名，系统提示词要求"给建议前必须查" |
| `get_user_history(days)` | 取最近 N 天记录 | 建议/反馈/饮食/自由输入 |
| `log_note(text)` | 记提取的条件 | 如从"加了三小时班"提取"到家晚、精力低"；回写 free_inputs.extracted_json 并进 conditions_json |
| `calc_body_metrics()` | 确定性计算 | Mifflin-St Jeor 公式算 BMR/TDEE/蛋白质区间，**写死在 Python 里，模型不许心算**；档案缺参数则返回不可用。提示词额外规定：本轮没调这个工具就不许在输出里出现任何 kcal/克数 |

### 2.3 注入的条件（每次调用的上下文）

系统提示词（固定规则 9 条：输出形状、建议必须小、理由必须回显真实条件、必须查手册标来源、饮食禁忌硬约束、疼/晕/胸口不适只建议休息就医、精疲力尽时主动撤运动、起床时间倒推几点停、只输出 JSON）之后拼：

```
【用户档案】下班时间/加班频率/通勤/身体状态/起床时间/能否做饭/禁忌/运动基础/身体参数
【当前虚拟时间】2026-08-13 19:05 （周四）
【今天已知】到家时间估计（下班时间+通勤算的）/ 今日饮食记录 / 自由输入原话 / 一击纠正项
【最近3天】每天建议了什么、反馈是什么
【当前最低线档位】N（含档位表说明）
```

这就是"记忆"：结构化记录直接注入，不做向量记忆库。

### 2.4 输出与安全

最终输出是固定 JSON：`judgement / reason / eat / move / stop / sources / safety_flag`。
`safety_flag=true`（用户提到疼/晕/胸口不适等）时前端只渲染休息/就医提示。后端校验能 `json.loads` 且 judgement、stop 存在，否则重试→兜底。

## 三、更新机制（次日调整，7.4 档位规则）

`baseline_level` 0–4 档写死一张表（4=15–20分钟 … 1=只有几点停，0=只说早点睡）。**不是学习模块，是简单规则**：

| 昨晚回执 | 今天档位 |
|---|---|
| 完成了 | +0；连续两天完成 +1（封顶 4） |
| 只完成一部分 / 跳过 | 不变 |
| 完全没完成 / 未响应 / 建议仍然太难 | −1（地板 0） |

- 计算时机：每天第一次点「下班了」时，由 `_compute_today_baseline()` 从昨天那行记录推出。
- 档位只约束**量级**（作为上下文告诉 Agent"建议量级：5分钟以内"），具体内容仍由 Agent 结合手册和当天条件生成——有机制但不是决策树。
- 连续几天没打开：旧的待回执记录标"未响应"（沉默也是数据），只对最近一天弹回执。
- **改回执的连锁**：用户当天内修改昨晚回执 → 重算今天档位 → 若变化则自动按新档位重跑 Agent 重出今晚建议。

## 四、RAG 方法

**语料**：6 份权威手册（中国膳食指南2022、中国身体活动指南2021、WHO 2020、全民健身指南、办公族拉伸、睡眠卫生），`scripts/crawl_corpus.py` 抓取+清洗为 markdown 放 `data/corpus/`（4 个反爬来源人工补齐，文件头注明）。英文来源保留英文——向量模型跨语言检索没问题（实测中文查询能命中英文拉伸/睡眠块）。

**构建**（`scripts/build_corpus.py`，幂等）：按标题/空行切块，每块 300–500 字、块首拼文档名 → 批量调 `text-embedding-v4`（1024 维）→ 文本进 `corpus_chunks` 表、向量存 `data/corpus.npz`（行号=id-1）。当前共 **59 块**。

**检索**（`rag.py`）：query 向量化 → 与全部向量算余弦相似度（numpy 一行，暴力全扫）→ 按 category 过滤 → top-3。几十毫秒级，**不装向量数据库**。

**引用**：检索结果带来源名回给 Agent，最终 JSON 的 `sources` 在界面上渲染成"参考依据"小字，轨迹面板也展示每次检索了哪本手册。

## 五、页面状态机与虚拟时钟

- 前端开屏调 `GET /api/state`，后端根据数据库判定视图：无档案→onboarding；今天已有建议→advice（卡片）；否则→home（下班了大按钮）。另带昨日待回执/已回执信息、今日饮食、虚拟时间。**界面回到哪儿全靠这个接口，前端不自己记。**
- 虚拟时钟存 `app_clock` 表，`POST /api/clock` 支持 +N小时/下一天(跳到次日19:00)/set/重置。改完时间前端重新拉 state，界面自然切换（"第二天打开先收回执"就是这么演出来的）。

## 六、全流程例子（真实数据，来自 M7 验收）

用户 `demo_m7`（27岁女，久坐，通勤45分钟，19:00 下班，07:00 起床，不吃辣，160cm/50kg）：

**第 1 天 19:10 — onboarding 完成，立即生成首夜建议（档位 3）**
Agent 轮次：查手册（diet/exercise/sleep 各一次）→ `calc_body_metrics` → 结论。
输出理由行："27岁女性、无运动基础、久坐上班、到家时间约19:45"（19:00+45分钟通勤是算出来的）；动="靠墙静蹲2分钟+坐姿猫牛式5次+肩颈绕环2分钟（共约8分钟）"（档位3量级）；来源：膳食指南2022、身体活动指南2021、睡眠卫生。

**第 2 天 12:30 — 拍了一张咖喱饭便当**
qwen-vl-max 识别：`{"名称":"咖喱饭","备注":"鸡肉,胡萝卜,鸡蛋,西兰花,青豆,米饭,咖喱酱"}` → 存 meal_records → 轻确认"记下了：咖喱饭。晚上给你参考。"（不评判、不触发建议）。

**第 2 天 19:05 — 点「下班了」**
后端发现昨天有 pending_feedback → 先弹回执屏"昨晚『靠墙静蹲…』做得怎么样？"→ 用户选「只完成一部分」（档位不变=3）→ 紧接着生成今晚建议，理由行已引用"今日已摄入咖喱饭"，晚餐建议往清淡补绿叶菜方向。

**同晚 — 自由输入"加了三个小时班累死了"**
原话存 free_inputs → 重跑 Agent。轮次：`log_note`（提取"加班3小时，到家晚、精疲力尽"）→ 查睡眠手册 → 查饮食手册 → 结论。**输出：move=null（运动整个撤掉）**，只剩"清淡外卖"和"22:45 放下手机"（07:00 起床倒推留足约 7 小时睡眠），来源：睡眠卫生、膳食指南2022。这就是 PRD 指定"最该演的一帧"。

**次日再点「下班了」**
先弹昨晚回执 → 按 7.4 调档 → 循环继续。若用户点错回执，卡片上方"昨晚记为：X（点错了？改）"可改，档位变化时今晚建议自动重出。

## 七、兜底清单（演示不死的保证）

| 失败点 | 兜底 |
|---|---|
| chat 模型调用失败 / JSON 解析两次失败 / 6 轮不收敛且强制收敛失败 | 返回写死默认建议（饭后走8分钟 / 23:00放下手机），trace 与日志留痕 |
| 视觉识别失败 | 按"一餐饭"入库，轻确认不报错 |
| RAG 语料缺失 / embed 失败 | `search_reference` 返回空列表，Agent 仍能出建议（只是没来源） |
| 所有模型调用 | 30 秒超时 + 1 次自动重试（llm.py 统一处理） |
