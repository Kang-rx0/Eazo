## 二、核心设计（对应 V2 文档 3.1/3.2）

等级排序：`none < caution < danger < crisis`。L1 输出分两部分：

- **锁定下界 `locked_level`**：硬词（急性红词、心理危机、严重疾病）和组合规则（慢性病×运动意图、用药）给出。**任何模型无权降级**。
- **候选等级 `candidate_level`**：软词（疼/晕/不舒服…、心理低落）给出。S2 的 L2 分类器可结合上下文降到 none（处理"不疼了"否定式），也可升级。

合并纯函数：`final = max(locked_level, L2结果)`；**L2 缺席/失败/输出非法值时 `final = max(locked_level, candidate_level)`**——分类器断网系统仍保守安全（宁可误报）。

## 五、开发中发现并修掉的两个覆盖缺口

1. **"胸口有点闷"接不住**：基线用例 1 的原话在部位和症状之间插了"有点"，纯子串匹配不到词表里的"胸口闷"。已加标准库正则的间隔变体规则（`胸/心口 + ≤4字 + 闷/疼/痛`、`喘不…气`），命中效果与硬词完全相同。
2. **"不太舒服"接不住**："不舒服"不是"不太舒服"的子串——而这正是 V1 纠正按钮的原文案。已把"不太舒服/不大舒服"整词补进软词表。

## 六、已知局限（设计内，留给后续阶段）

1. **否定式误报**（V2 文档 S0 验证条目明确预期）："现在不疼了"仍报 caution。它是**候选**而非锁定——S2 的 L2 分类器上线后可降回 none，纠正通道已留好。
2. 严重疾病清单和求助热线文案均为**占位**，逐项等你确认（V2 文档 4.4 / 五）。
3. `enforce()` 目前只补字段（safety_level/avoid/see_doctor）不改内容，强制改写、数字校验、诊断断言过滤在 S1 实现。
