  2. **口味偏好八类**（PRD 原表）：多选存 `profiles.favorite_foods`，注入【口味偏好】带每类"最轻的改法"；优先级 医嘱 > 饮食禁忌 > 安全 > 偏好。

  4. **下班提醒条**：到档案设定下班时间弹一条；「还没」30 分钟后再问一次；再拒绝当天不再问。纯前端实现（localStorage + 30s 轮询虚拟时钟）。

## 六、advice JSON 契约（前端整合必读）

V1 字段：`judgement / reason / eat / move / stop / sources / safety_flag`（+`agent_notes`）。
**V2 新增**：`safety_level`（none/caution/danger/crisis）、`avoid`（字符串数组）、`see_doctor`（字符串或 null）、`disclaimer`（慢性病尾注）、`severe_notice`（产品不适用提示）。
接口新增行为：`/api/offwork` 可带 `{"state": "今晚更累"}`；`/api/correct` 支持 `难度再低一点/难度再高一点`（到边界返回 `{ok, message, advice}` 不重生成）；`/api/state` 可能返回 `view="rejected"+message`；offwork/correct/free_input 对劝退用户返回 `{rejected: true, message}`。
**V3 新增**（全部增量，旧字段不动）：
- `/api/state` 在 home/advice 视图附加 `confirm_hint`：`{sleep_point, home_eta, remaining_min, time_basis, energy_guess, energy_basis, body}`（纯代码估算，body 永远"暂未确认"）。
- `/api/offwork` 第三种 payload：`{"calibration": {"time_budget_min": 60|null, "energy": "几乎没有|很低|还行", "body": "没有明显不适|有明显不适|暂未确认"}}`——state 与 calibration 同传时 state 优先；映射为既有机制（body 不适→下班状态"不太舒服"、精力低→"今晚更累"、时间只紧不松记 conditions["剩余分钟"]），派生行随 conditions 每次重生成继续带。
- `/api/correct` 新类型 `换一种做法`：一次性条件（不写入 conditions["纠正"]），档位不变，带上一版 eat/move 摘要。
- `GET /api/history`：`{"history": [{vday, line, items}]}` 倒序上限 30，**绝不含 feedback、绝不含连续天数**；severe 用户返回 `{rejected: true, message}`。
- 口味偏好八类定稿名：`粉面、炸物快餐、盖饭便当、火锅麻辣烫、烧烤夜宵、甜品饮料、轻食沙拉、自己做的家常`（写入端归一化旧名，读取端归一化兜底，`agent.FAVORITE_FOOD_ALIASES` 不可删）。

**V3 反馈修改新增**（2026-08-09，详见 `docs/V3/记录/反馈修改-*-验证记录.md`）：
- advice 新增**可选**字段 `focus`：judgement 里的原文片段（2~6 字），供结论屏大字做琥珀高亮。**可能为 null**，前端必须能整句平铺。`safety.enforce` 出口保证 `focus` 要么是 `judgement` 的子串、要么是 `None`——L3 改写过 judgement 就自动作废。`_parse_advice` 的必填校验不变（仍只要求 judgement/stop）。
- `/api/clock` 新增 `advance_minutes`；三个 `advance_*` 均支持负数；`reset` 语义改为回演示起点 `clock.DEMO_START`（2026-08-24 16:00），`advance_days` 落点同为 16:00。
- `profiles.off_work_start` 语义澄清为**上班时间**（onboarding ob-1 左轮），列名沿用历史；提示词注入行改为 `上班 X，下班 Y，加班频率`。
- `profiles.cooking` 改存自然语言四选：`大多点外卖 / 主要吃食堂 / 基本自己做 / 几样混着来`（旧三值不迁移，前端预填时映射；后端无枚举校验），提示词注入行改为 `平时吃饭：{cooking}`。

## 七、与队友原型整合的注意事项（2026-08-08 立项；**2026-08-09 已按此完成，本节保留作硬要求清单**）

队友产出：design 文档 + HTML 原型；**整合原则：视觉与页面结构以队友为主**。但以下功能元素是硬要求，不管长什么样都必须存在（多数是安全边界，丢了等于回退）：

1. **建议卡的安全渲染**：avoid 清单（"今晚先不："）、see_doctor 就医行、disclaimer 尾注、severe_notice、危机整卡（只有关怀语+停+就医行）。字段为空时隐藏（正常用户界面零安全元素）。
2. **劝退视图**（view=rejected）：温和文案 + 「我的资料」修改出口（这是 severe 误报的唯一纠正通道）。
3. **onboarding 三件套**：确诊疾病自由填写输入框（+填了才展开的医嘱框）、口味偏好八类多选、原有档案字段。编辑模式（?edit=1）预填。
4. **下班流程**：状态四选一（可跳过）→ 生成；建议卡难度微调两按钮（安全模式下隐藏"再加一点"）；一击纠正五按钮；下班提醒条逻辑。
5. **回执流**（昨晚四档+跳过、"点错了？改"）、自由输入框、拍照入口、trace 侧栏（含"安全层：…"行）、虚拟时钟控制条、toast 反馈（所有改动必有明确反馈，不允许静默）。
6. 后端 API 与 JSON 契约（第六节）不因换皮而变；整合期间不改 backend/ 行为，每整合完一个页面跑 `scripts/safety_regression.py` + 浏览器人眼。

## 八、踩过的坑（改动前先理解）

1. `backend/agent.py` 提示词三条是修 bug 修出来的（禁带数字示例/精疲力尽撤运动/没调工具不出数字），V1 交接文档有详情；V2 又加了：规则 7 的"系统会在你之外做安全检查"、规则 11 医嘱硬约束——都别删。
2. 【安全状态】注入行尾的"不要复述"指令 + enforce 的内部术语清除是配套的（模型会把注入行当条件抄进理由）。
3. L3 血压数字正则排除了括号/书名号——《高血压食养指南(2023)》的年份不是血压值。
4. 数字删除后会清理空括号（"少油（<5g）"→"少油"）。
5. crawl_corpus 的截断标记取**最后一次**出现（目录里有同名条目会误伤）。
6. 已知未修（用户知情）：A1 同步 LLM 调用阻塞事件循环（单用户演示无感）；A2 /api/clock 无鉴权（演示道具）；正常用户检索偶尔命中高血压食养指南（内容无害，优化项）。
7. V3 已知边界（详见 docs/V3/记录/ 各步"问题与潜在问题"节）：安全夜问法、停下提示屏、历史分页为后续需求未做；结论屏时间带的"路上"段在未到下班点时会把等待时间画进去（晚间演示无碍）；编辑态病况 chips 只增不删（删病名直接改输入框整句）；`_MED_NUM_RE` 对"血糖7点几"这类模糊口语不删（无具体数值，非漏报）。
