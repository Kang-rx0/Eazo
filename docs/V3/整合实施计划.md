## 二、P0：血压数字误删 bug（队友反馈，独立先修）

**现象**：与血压/血糖无关的数字（时长、时刻、日期）偶发被 L3 数字禁区误删，句子被删得残缺。

**根因**：`backend/safety.py` `_MED_NUM_RE` 第二分支
`(?:血压|血糖)[^，。；！？()（）《》]{0,6}?\d+(?:[./]\d+(?:\.\d+)?)*`
——只要"血压/血糖"后 6 字内出现任何数字就把整段删掉。已确认的误伤形态：

- `量完血压再走10分钟` → 命中"血压再走10" → 残句"量完分钟"
- `高血压人群晚上8点后不建议剧烈运动` → 命中"血压人群晚上8"
- `睡前测个血压 22:30 上床` → 命中"血压 22"，残留"：30 上床"
- `成人高血压食养指南2023版`（不带括号书名时）→ 命中"血压食养指南2023"

**修法**（S0 步骤）：第二分支收紧为"像读数才删"，三个条件取并：
1. 数字呈血压读数形态：`\d{2,3}\s*/\s*\d{2,3}`（如 140/90），间隔仍限 6 字；
2. 或 间隔里含取值语境词：`控制在|不超过|超过|低于|高于|降到|达到|目标|保持在`（覆盖现有单测"血压控制在140/90mmHg""血糖不超过7.8"）；
3. 或 血糖 + 紧邻（≤2 字）的小数（如"血糖7.8"）。
   同时排除数字后紧跟 `分钟|小时|点(?!几)|年|月|日|版|次|步` 的匹配（时间/时长/版次不是读数）。
   第一分支（带 mmHg/mmol 单位）不动——有单位的永远删。

**新增单测（≥6 个）**：上面 4 个误伤句必须**零改写**；`血压控制在140/90mmHg以内`、`血糖不超过7.8`、`血压140/90`、`血糖7.8` 必须仍被删。现有 `test_数字校验_*`、文献名括号用例不许回归。

**牵连检查**：`scripts/test_safety.py` 68 全绿；`safety_regression.py` 18/18（用例 14/15 断言"无血压血糖数字"，必须仍绿）；`docs/安全边界测试记录.md` 追加一行说明。

**验收**：单测 + 回归 + 用误伤句起真实服务复现一次（修前删、修后留）。

## 三、P1：后端配合改动（B1–B5，全部**增量式**，旧契约不破坏）

> 总原则：`/api/*` 现有字段与行为原样保留（回归脚本、旧前端在整合中途仍能跑）；新能力全部走新增字段/新增类型/新增接口。每个 B 步骤完成即跑全量单测+回归。

### B1 `/api/state` 新增 `confirm_hint`（s-confirm 三行判断的数据源）

- **改动**：`main.py` `api_state` 在 view 为 home/advice 时附加：
  ```json
  "confirm_hint": {
    "sleep_point": "23:30",        // wake_time 倒推（保证约7.5h 睡眠机会，与提示词规则3同口径）；无 wake_time 按 23:00
    "home_eta": "22:36",           // 虚拟现在 + commute_min（已过下班点则从现在起算；口径与 agent._estimate_home_time 一致，抽公共函数）
    "remaining_min": 54,           // max(0, sleep_point − max(now, home_eta))，纯代码计算
    "time_basis": "按 23:30 的睡点和 30 分钟通勤倒着算的",
    "energy_guess": "很低",         // 昨晚回执∈{完全没完成,建议仍然太难,未响应} 或 今日档位≤1 → "很低"；否则 "还行"
    "energy_basis": "昨晚那条没做完，今晚先按省力的来",   // 只引用真实数据，不虚构"在忙了12小时"
    "body": "暂未确认"              // 永远这个值：身体状况后端判断不了，按用户说的算
  }
  ```
- **牵连检查**：纯新增字段，旧前端忽略即可；`clock` 虚拟时间是唯一时间源；basis 文案不得出现内部术语；**不写库、不调模型**（纯函数），单测覆盖 sleep_point/remaining 的边界（跨零点、已过睡点→0、无档案字段）。
- **验收**：单测 + 手工 curl 三种档案形态（有/无 wake_time、拨时钟到睡点后）。

### B2 `/api/offwork` 新增 `calibration` 参数（结构化校准入口）

- **改动**：payload 兼容三种：`{}`（不变）、`{"state": …}`（不变，回归在用）、新增
  `{"calibration": {"time_budget_min": 60|null, "energy": "几乎没有|很低|还行", "body": "没有明显不适|有明显不适|暂未确认"}}`。
  映射为既有机制（**不新造安全通道**）：
  | 校准输入 | 落点 |
  |---|---|
  | `body=有明显不适` | conditions["下班状态"]="不太舒服" → 既有路径：进安全扫描文本（急性软词命中）+ 上下文注入 |
  | `energy∈{几乎没有,很低}` | conditions["下班状态"]="今晚更累"（body 已占用时 energy 降级为补充条件行） |
  | `time_budget_min < confirm_hint.remaining_min` | 补充条件行"用户说今晚只剩约 X 分钟，几点停按它收紧"；conditions 记 `{"剩余分钟": X}` |
  | `energy=还行` 且无其他 | conditions["下班状态"]="今天还行" |
  | 全默认/未传 | 与 `{}` 完全一致 |
  原始 calibration 原样存入 conditions（重生成时继续带着）。
- **牵连检查**（这是 3-7 的牵连重点，逐条核）：
  1. `_run_and_save_today` 的"下班状态"注入行、安全扫描 texts 追加逻辑**复用不改**——映射后行为与老四选一完全同构；
  2. "不太舒服"照样过三层检测（追加验证 D 用例语义不变）；
  3. 慢性病封顶 3、档位规则、severe 守卫全部不碰；
  4. `OFFWORK_STATES`、`{"state"}` 分支保留 → `safety_regression.py` 与追加验证脚本零改动仍绿；
  5. 双击锁、need_feedback 优先于生成的顺序不变（校准值暂存在前端，回执收完后重新提交）。
- **新增单测**：映射表 5 行各一个 + body 优先于 energy + calibration 与 state 同传时 state 优先（防歧义）。
- **验收**：单测 + 回归 18/18 + curl 实测"有明显不适"路径 safety_level=caution。

### B3 `/api/correct` 新增类型「换一种做法」

- **改动**：`CORRECT_TYPES` 增加"换一种做法"。处理为**一次性条件**（参照难度微调的做法，不写入 conditions["纠正"]——写入会让"换个做法"永久跟着每次重生成，方向漂移）：
  - 档位不变、不查封顶；
  - extra_conditions 追加：`用户希望换一种做法：目标和量级保持不变，给出与上一版不同的具体做法（上一版：吃={eat}；动={move}）`（eat/move 为 null 时省略）；
  - 安全模式照常：重生成结果仍全量过 `enforce`（danger/caution 下换出来的运动照样被撤）；crisis 与 rejected 用户走既有拒绝分支，前端在这两种状态下隐藏该按钮。
- **牵连检查**：
  1. 措辞"换一种做法"过一遍词表确认零命中（无运动意图词/无软词），不会被组合规则拦；
  2. conditions["纠正"] 语义不变——依赖它的回执连锁 (`api_feedback`)、自由输入重跑的 extra 拼接不受影响；
  3. `CORRECT_TYPES` 是白名单校验，加项不影响旧项；
  4. 上一版 eat/move 注入的文本也会进下一轮 trace，但**不进安全扫描 texts**（extra_conditions 本来就不扫，与"难度再高一点不进扫描"同一设计）。
- **新增单测**：类型合法性 + 不写入纠正列表 + 上一版摘要拼接正确。
- **验收**：单测 + 回归 + 真实服务连点两次"换一种做法"，两版 move/eat 确实不同且档位不变。

### B4 新增只读接口 `GET /api/history`（历史回看的数据源）

  `{"vday": "...", "line": "<advice.stop 或 judgement 摘要>", "items": [eat/move/stop 的非空行]}`，上限 30 条。

- **牵连检查**：只读不写库；不调模型；对 `get_pending_records_before` 等现有查询无影响。
- **新增单测**：无记录→空数组；含 feedback 的记录返回体里无 feedback 字段；上限截断。
- **验收**：单测 + curl demo1（有多天记录的种子号）。
