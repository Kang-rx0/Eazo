## 二、体验前必知：哪些是"AI 想的"，哪些是"代码算的"

体验时最容易误会的一点：**不是所有输出都来自大模型。**

| 界面元素 | 来源 | 出处 |
|---|---|---|
| s-confirm 三行判断（剩余时间/精力/身体） | **纯代码**（`agent.build_confirm_hint`，不调模型）：睡点=起床倒推7.5h、剩余=睡点−到家、精力=昨晚回执+档位的固定映射、身体永远"暂未确认" | 队友 DESIGN.md s-confirm 节；差异清单 ③-7；实施计划 B1（用户拍板"按队友设计做，后端配合"） |
| s-confirm 标题（"今晚先按省力的来"/"先对一下今晚的判断"） | **前端两句固定文案**按 energy_guess 切换 | P4 记录问题 2（文案可改） |
| 结论屏 judgement/reason/eat/move/stop | **LLM 生成**（走三层安全检测与 L3 强制改写） | V2 架构 |
| avoid/see_doctor/disclaimer/危机文案/劝退文案 | **定稿常量**（`backend/safety.py` 常量区，改动须用户再确认） | 交接文档二-7 |
| 时间带（路上 X 分/在家 Y 分） | **纯代码**（confirm_hint + 档案通勤） | 实施计划 ③-13 |
| 历史回看列表 | **只读库查询**（不调模型、绝不含 feedback/连续天数） | B4 |
| 食记确认句（"记下了：煎蛋"） | **视觉模型识别** | V1 |

## 三、体验路线建议（约 15 分钟）

1. **正常晚**：demo1 登录 → 开始今晚 → 回执答"做到了" → 看结论屏（时间带/理由行/trace 折叠）→ 我要补充 → 再轻一点 / 换一种做法 → 就这样（印章屏）。
2. **校准**：时钟拨下一天 → 开始今晚 → 三行判断点「改一下」→ 拨时间/选精力 → 按这个重新算。
3. **安全路径**（用新注册号，别烧 demo 人设）：树洞输入"胸口闷喘不上气"再生成 → danger 灰卡；另注册一号 onboarding 点"心脏病"chip → 劝退屏 → 改一下刚才那项改成高血压 → 解除。
4. **设置**：齿轮 → 五分组（提醒开关/回看/关于）。
5. 新号完整走一遍六步 onboarding（含滚轮和跳过）。

## 四、已知问题与潜在问题汇总（体验时对照，别重复报）

详细版散在 `docs/V3/记录/*-验证记录.md` 各自的"问题与潜在问题"节，这里收拢：

**产品决策类（改起来要先想清楚）**
1. s-confirm 每晚必出（③-7 决策的直接结果）；觉得烦可以改成"仅首夜/仅异常时出现"，纯前端改动。
2. 精力两档合并："几乎没有"和"很低"映射后提示词看不出差别（原始值在 conditions["校准"] 里，要细分可从这取）。
3. 时间预算宁紧不松：校准里把时间调宽不生效（B2 设计）；睡点已过时时间校准整体失效。
4. 停下提示屏（到点提醒睡）、安全夜问法、历史分页：后续需求，本期未做。
5. 编辑态病况 chips 只增不删：删病名要在输入框里改整句。

**体验瑕疵类（改起来低风险）**
6. 结论屏时间带的"路上"段在未到下班点时把等待时间也画进去，下午看偏大。
7. 历史 line 用 stop 原文，长句折行；副行截 60 字。
8. s-confirm 标题/树洞"说给它"提交件是整合时定的文案与形态，可随喜好换。
9. 30s 轮询只刷时钟与提醒条，不主动切视图（防打断）；拨时钟按钮才全量刷新。

**环境类**
10. A1 同步 LLM 阻塞事件循环（多人同时点会排队，双人体验基本无感，卡就等几秒）。
11. 浏览器体验务必走 http://localhost:8100 ，别用 file:// 直开页面（fetch 会被拦，P6 记录二有踩坑留档）。
12. 服务不带 --reload：改了 backend/ 要重启 uvicorn；改 frontend/ 刷新页面即可（注意浏览器缓存，强刷）。

## 五、新会话修改时的硬约束（违反算错）

1. conda 环境 `Eazo`、8100 端口；git 提交**永不加 Co-Authored-By**；`.env` 只认 LLM_API_KEY/LLM_BASE_URL 不动不进 git。
2. 只在 **ui-integration** 分支工作、只推这个分支。
3. `backend/safety.py` 常量区定稿文案（劝退/尾注/危机）改前必须先问用户。
4. 每次后端改动的回归底线：`scripts/test_safety.py` 全绿（现 106 个）+ `scripts/safety_regression.py` 18/18；前端改动加浏览器人眼。
5. 安全宪法：只能加严不能降级；无热线，只建议就医；正常用户界面零安全元素。
6. 改动前过一遍 `docs/V3/整合实施计划.md` 第六节"全局牵连总表"；口味偏好类名、correct 类型字符串、FEEDBACK_OPTIONS 这些枚举是前后端契约，两端要一起动。
7. 每步产出验证记录（docs/V3/记录/，含"问题与潜在问题"节），等用户确认再进下一步。

## 六、反馈怎么记最好改

体验时每条问题记三样：**哪个屏（或哪一步）→ 期望什么 → 实际什么**。若涉及文案，直接给定稿新文案（尤其安全类文案，给了才能改）。分不清是"模型输出问题"还是"界面问题"时，对照本文第二节的表：模型输出问题去调提示词/安全层（谨慎），界面问题改前端（低风险）。
