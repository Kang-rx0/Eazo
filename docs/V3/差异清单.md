## ② 队友原型缺失的功能元素 —— 对照交接文档第七节逐项标注

**判定口径：丢了等于安全边界回退或 V1/V2 已验收功能回退，整合时必须以队友的设计语言补齐。**

### 硬要求 1：建议卡的安全渲染

| # | 硬要求 | 原型现状 | 结论 |
|---|---|---|---|
| 2-1 | avoid 清单「今晚先不：」 | **缺失**。原型没有渲染 `avoid` 数组的任何位置 | 补。建议做成结论屏 plan 列表下方的一个专用区块，沿用 sober/中性色，不做红色警报 |
| 2-2 | see_doctor 就医行 | **缺失**（s-safety 有一句写死的"不适明显请联系专业医疗人员"，不是按建议卡字段渲染） | 补。字段有值才出现，逐字用后端文案 |
| 2-3 | disclaimer 慢性病尾注 | **部分**：s-chronic 有一条写死的"以你的诊疗方案为准"note | 改为渲染后端 `disclaimer` 字段（两条尾注文案已定稿，不许前端改写），空则隐藏。note 组件样式可直接用 |
| 2-4 | severe_notice 产品不适用提示 | **缺失** | 补（自由输入触发严重疾病标记时当晚建议卡附带） |
| 2-5 | 危机整卡（只有关怀语+停+就医行） | **缺失**。s-safety 是"身体不舒服"通用停下屏，没有 crisis 定稿文案路径 | 补。crisis 时整卡替换（后端已把内容换成定稿求助文案，前端照常走统一渲染即可），配 sober 模式 |
| 2-6 | 字段为空时全部隐藏（正常界面零安全元素） | 原型天然满足（因为压根没有这些元素） | 整合时必须保住：所有安全元素都按"有值才渲染" |

## ③ 交互流程 / 接口假设冲突 —— 逐条建议取舍

| # | 冲突 | 两边现状 | 我的建议 |
|---|---|---|---|
| 3-1 | **单文件 SPA vs 四页面** | 原型是一个 html 内 30+ 屏切换；现有是 4 个页面各自拉接口 | **保留四文件结构**：index.html=welcome tour、auth.html=登录、onboarding.html=分步表单（含编辑态）、app.html=Home/状态四选一/结论屏/安全屏/设置等多屏切换（把原型的 show()/返回栈机制搬进 app.html）。理由：与后端按 view 跳转的现有约定吻合，也符合"每整合完一个页面验收一次"的节奏 |
| 3-2 | **无账号本地存储 vs token 鉴权** | 原型宣称"全存本机、不注册也能用"，s-set-account 整屏文案都基于此 | **以后端为准**：保留注册/登录 + token。s-set-account 文案改写（去掉"没有上传"的不实描述），「清空我的数据」后端无对应接口→本期改成「退出登录」；「换手机接着用」壳屏直接删（我们本来就有账号） |
| 3-3 | **真实设备时间 vs 虚拟时钟** | 原型所有"现在"读 `new Date()`，睡点=现在+80分钟启发式 | **以后端为准**：一切时间显示与判断用 `/api/state` 的 virtual_now（30s 轮询已有），保留时钟控制条。原型的 greetingFor/顶部时钟照用，只换数据源 |
| 3-4 | **前端本地"伪 Agent" vs 后端真建议** | 原型 renderPlan() 是写死的演示逻辑（正则抽火锅/加班、本地拼文案）；建议四维、理由行、时间带全是脚本 | **全部换成后端 advice JSON 渲染**：judgement→结论屏 H1/判断行、reason→理由行（source-row）、eat/move/stop→plan 清单三行（null 不渲染，符合原型"维度可缺席"设计）、sources→理由行来源、V2 五字段按 ②-1~5 补。原型的本地正则抽取逻辑全部删除 |
| 3-5 | **病况输入形态**：病名 chips + 前端分类 vs 定稿的自由填写单框 | 原型 ob-4 三个病名 chip + JS 里 REFUSE/CHRONIC 词表现场分流劝退 | **以已定稿的产品决策为准**：单个自由填写输入框（"自己的话写就行"）+ 填了才展开的医嘱框；**前端词表整段删除**，慢性/严重/无的判断只在后端。队友的 chips 若想保留，可降级为"点一下往输入框里填字"的快捷键，不参与任何判断（可选，默认建议不留，避免暗示只有三种病） |
| 3-6 | **劝退触发源**：前端 healthRoute() 现场跳 s-refuse vs 后端 view=rejected | 原型填完第 4 步立即前端判词跳劝退 | **后端为准**：onboarding 提交后按 `/api/state` 的 view 决定去向（rejected→劝退屏）；offwork/correct/free_input 返回 `{rejected:true}` 同样转劝退屏。前端不做任何医学词判断。s-refuse 的"命中即停"注释文案删掉（那是前端词表的说法） |
| 3-7 | **s-confirm 三行估算（剩余时间/精力/身体）+ 改一下抽屉** | 后端没有"估算剩余时间/精力"的任何数据源，这三行是原型虚构的演示数据；后端的对应物是状态四选一 | **替换**：点「开始今晚」→ 状态四选一屏（今天还行/今晚更累/时间更少/不太舒服 + 跳过，用 option 组件）→ 调 `/api/offwork {state}`。**adjust-sheet（时间滚轮+精力+身体三项校准）本期整体不接**——它假设的结构化重算入口后端不存在，摆出来就是假交互（原型自己的硬规则也反对假交互）。保留代码可留作后续需求 |
| 3-8 | **回执三档/安全夜问法 vs 后端四档+跳过** | 原型 recall 分 plan 夜（3 档）和 safety 夜（好多了/差不多/还不太好）；后端 `/api/feedback` 只认四档+跳过，且没有"安全夜改问关心句"的机制 | 四档+跳过按 ②-20 补齐（映射：做到了→完成了、做了点→只完成一部分、没顾上→完全没完成，另补「建议仍然太难」「跳过」）。**安全夜问法本期不做**（需要后端区分记录类型，违反"不改 backend"），记入后续需求。回执触发时机也以后端为准：offwork 返回 need_feedback 才弹回顾卡，不在 Home 常驻 |
| 3-9 | **sober 安全模式的触发映射** | 原型 sober 只由"身体不舒服"按钮和劝退屏触发；我们的安全等级来自后端 safety_level | 建议映射：`crisis`→整卡替换+sober（危机定稿文案）；`danger`→建议卡 sober（灰阶、语音句退场）；`caution`→**不进 sober**，正常配色 + avoid/就医行/尾注（对应 DESIGN.md 说的"慢病场景半退场"，慢性病日常卡按 S6 验收样子：镣铐可见但不扎眼）；`view=rejected`→劝退屏 sober。「身体不舒服」安全出口按钮保留，行为改为发送 `/api/correct {type:"不太舒服"}`（正好是后端已验收的入口），不再只跳静态屏 |
| 3-10 | **s-history 无后端接口** | 原型历史来自 localStorage；后端没有历史列表 API（不改 backend） | **本期隐藏「回看」分组**，屏和组件代码保留。若你想要，可退一步用前端本地记录（接受过的建议存 localStorage）——但换设备就丢，且与"数据在账号上"矛盾，默认建议隐藏 |
| 3-11 | **推送/停下提示设置组** | 原型有 推送开关/推送时间/顺延次数/停下提示 四项；后端没有推送，网页版对应物只有下班提醒条 | 「下班时找我」开关→控制下班提醒条开与关（纯前端 localStorage）；推送时间/顺延次数/停下提示三项**本期隐藏**（顺延逻辑我们已固定为 30 分钟×2 次，不做成可调项，避免假设置） |
| 3-12 | **「清空并重走一遍」等原型演示夹具** | s-set-about 里有三个演示跳转 | 删除（我们真正的演示道具是虚拟时钟条）。「值夜会做什么/不做什么/数据在哪」关于屏保留，文案按真实行为改写（数据存服务端账号下、照片会被识别用于饮食记录） |
| 3-13 | **时间带（time band）的数据源** | 原型用 现在+通勤+启发式睡点 画带 | 保留组件：now=虚拟时钟、通勤=档案 commute_min、睡点=advice.stop 里解析出的时间（解析不到就整条带隐藏——组件本身允许缺席，不硬凑）。"今晚需要你花的时间"一行原型是拍脑袋数字，删除或隐藏 |
