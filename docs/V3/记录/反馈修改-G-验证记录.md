## 一、落地清单

### ① 生成进行态：按钮变文案，不再浮框

- 生成建议时，主按钮「判断大致没错」原地变为「正在想今晚怎么安排，大约十几秒…」并禁用，结束后恢复原文案。
- 移除原来盖在按钮上的浮框 toast。
- 验证：DOM 确认 setLoading(true) 时按钮文案切换 + disabled=true + 无 toast；结束恢复原文案。

### ② 首次 onboarding 完成 → 直进确认屏

- 首夜（`?firstnight=1`）走完 onboarding 后直接进 s-confirm，标题「先对一下今晚的判断」+ 三行判断（剩余时间/精力/身体）。
- 验证：DOM 确认 active=s-confirm、标题正确、三行判断就位。

### ③ 合并「身体不舒服」入口

- 原来独立的「身体不舒服」按钮取消，合并进「我要补充」抽屉（下班屏 + 确认屏统一走补充）。
- 确认屏 foot 仅剩「判断大致没错 + 我要补充」，「身体不舒服」按钮已移除。
- 验证：截图确认确认屏无「身体不舒服」独立按钮。

### ④ 补充内容在 Home 常驻可见

- 用户补充过的话（free_input）在 Home 常驻列表显示「HH:MM 你说：XX」。
- 验证：DOM 确认 notesLog 可见、条目文案为「你说：…」。

### ⑤ 三个导航修复

- 设置屏「关于你」下改为 6 个精确字段入口（上下班时间 / 工作日身体 / 平时怎么吃饭 / 要绕开的 / 起床时间 / 常吃的东西），各带副标题。
- 每页右上角返回键（到用户点「就这样」进入锁定态后无返回）。
- 建议页底部「今天不做」低调入口（foot 顺序：就这样 ｜ 我要补充 ｜ 今天不做）。
- 验证：设置屏截图；建议页 foot DOM 确认 adviceBye 可见、文案「还是做吧」在 bye 屏可见。

### ⑥ 「我要补充」抽屉清理

- 抽屉只保留：补充一句（free 输入）+ 换个做法（换一种 / 再轻一点 / 再加一点）。
- 移除抽屉里的「昨晚反馈」等冗余项。
- 验证：截图确认抽屉内容精简到两组。

### ⑦ 高危信号（danger/crisis）硬退出到安全结束页

- 后端 /api/state 增加 `view: safety_exit` 判定：当天建议 `safety_level` 为 danger/crisis 时返回该 view。
- 前端 refreshState 命中 safety_exit：`clearNight()` + `currentAdvice=null`（强制退出任何锁定态、防止别处复活旧建议）→ renderSafetyExit → `show('safety-exit')`。
- 原则：**安全永远赢过「停在当前屏」和锁定态**。即使用户正停在已定页，安全升级也把他拉到安全结束页。
- 验证：造 danger 态 state，DOM 确认 active=safety-exit、锁定态已清。

### ⑧ 已定页卡片化（硬阴影 + 倾角 + 序号）

- 三条建议由平灰条重做为独立纸片卡：硬阴影 `box-shadow 5px 5px 0`（零模糊纯位移，和印章同语言）、序号徽标（21→30px、加边框，核心条琥珀色）。
- 印章（stop）是视觉峰值：6px 阴影 / 琥珀 / -1.2°；卡片在其下，统一不抢戏。
- 验证：真实 accepted 态截图确认硬阴影 / 序号 / 无裁切。

## 二、后续追加轮次（同分支陆续提交）

### 文案三处（advice 页，commit d023898）

- 「为什么是这条线」→「判断依据和来源」
- 「在家 X 分」→「可支配时间 X 分钟」；「路上 X 分」→「路上 X 分钟」（单位统一）

### home 已定态按钮（bug，commit d023898）

- 已定后从锁定页点「回首页」，home 主按钮仍是「开始今晚」（会重走确认/生成）。
- 修：`show('home')` 时按 `acceptedValid` 切文案——已定→「查看今晚建议」，未定→「开始今晚」；`startNight()` 开头判断已定则直接 `show('accepted')` 回已定页。
- 验证：探针实测 active=home 时 startBtn 文案=「查看今晚建议」。

### 已定页卡片交错倾角（bug，commit d023898）

- 原用 `nth-of-type` 按 DOM 固定位置定倾角，中间运动项缺席时剩下 eat/stop 都在奇数位、同向左偏。
- 修：renderLock 按「可见顺序」打 `data-tilt`（可见 1 左 / 2 右 / 3 左…），CSS 按标记给方向。
- 验证：move 缺席场景 DOM 确认 lockEat=l / lockMove hidden / lockStop=r，截图两卡反向。

### 开屏引导页文案打磨（第 2、3 屏，commit 6c4c7c0）

- 第 3 屏副文去 AI 味：旧「不跟明天比…就给到位，这就够…」→ 新「忘掉打卡，没有及格线，做到多少都算数。先认识你一下，以后每晚我替你想好。」
- 第 2 屏标题「是今晚这一件」→「先过好今晚」（产品给的是一整套安排，非单件）；副文精简去产品腔。
- 第 1 屏保留原版（用户确认）。
