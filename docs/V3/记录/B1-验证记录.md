# B1 验证记录：/api/state 新增 confirm_hint

> 日期：2026-08-09 ｜ 分支：ui-integration ｜ 改动文件：`backend/agent.py`（公共口径 + 新纯函数）、`backend/main.py`（api_state 组装）、`scripts/test_safety.py`（+11 单测）

## 一、改动内容（纯新增，旧契约零变化）

1. **`agent._estimate_home_time(p, now=None)`**：加可选 `now` 参数抽成公共口径。缺省调用（提示词【今天已知】注入）行为与原来逐字节一致；`now` 给定且已过下班点时改从现在起算（confirm_hint 专用）。
2. **`agent.build_confirm_hint(p, now, last_feedback, baseline_level)`**：新纯函数，不写库、不调模型。
   - `sleep_point`：挂在"下一次起床时间"上倒推 450 分钟（约 7.5h 睡眠机会，与提示词规则 3"约 7 小时以上"同口径）。挂下一次起床的写法天然处理两类边界：跨零点（起床 08:30 → 睡点次日 01:00）与睡点已过（remaining 归 0）。无 wake_time 按默认起床 06:30 → 睡点 23:00（与规则 3 默认一致）。
   - `home_eta`：与提示词注入共用 `_estimate_home_time`；档案缺下班时间时退化为 现在+通勤。
   - `remaining_min`：`max(0, sleep_point − max(now, home_eta))`，datetime 相减，跨日不出负数。
   - `energy_guess/energy_basis`：昨晚回执∈{完全没完成,建议仍然太难,未响应} 或 今日档位≤1 → "很低"，否则"还行"；basis 只引用真实数据（昨晚回执结果/安排已压低/暂无记录），逐句枚举、不虚构。
   - `body`：永远"暂未确认"。
3. **`main.api_state`**：有档案分支（view 必为 home/advice）组装 `confirm_hint`；今日档位取当日记录的 `baseline_level`（已生成建议时，难度微调后的真实档位），无当日记录则用 `_compute_today_baseline` 推算。响应体顶层新增 `confirm_hint` 键（onboarding/rejected 路径为 null/缺席），旧前端忽略即可。
