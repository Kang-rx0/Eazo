## 一、落地清单

### 1. 接受后锁定屏（第 7.2 条 + Q2）

`s-accepted` 从"印章 + 一颗返回按钮"改造成「今晚已定」死胡同：

**同构 DOM 的处理**：Home 与锁定屏各要一份树洞/食记，直接复制会撞 id。把整块改成 `[data-tools]` 容器 + 内部全 `data-*` 定位，JS 改用**事件委托 + 就近 `closest('[data-tools]')` 取元素**，两份共用一套逻辑。原来的 `freeTextHome / photoPick / photoInput / photoMsg / photoReceipt / photoDelete` 等全局 id 全部退场。

- 树洞提交 → `/api/free_input` → 当天已有建议就会重算 → **锁定屏三行同步刷新**，人不离开锁定屏；
- 若重算后升级到 danger/crisis → **清掉锁定态、退出锁定屏**转 sober 卡（安全永远赢过锁定）；
- 食记只做识别记录，不触发重算（现行为，Q2 明确保持）。

**接受状态不落库**（维持 ①-8）：`localStorage.accepted_vday`。

### 2. 睡点弹窗（第 7.2 条）

- 睡点解析：先用 `/([01]?\d|2[0-3]):[0-5]\d/` 从 `advice.stop` 原文里抽，抽不到回落 `confirm_hint.sleep_point`；
- 触发：`virtual_now ≥ 睡点` **且**处于锁定屏。检测点有三处——进锁定屏时立即一次（接受时已过点就马上弹）、拨时钟后一次、30s 轮询一次；已经开着就不重复弹；
- 复用 `nightwatch.css` 里现成未用的 `.scrim / .modalwrap / .modal`；
- 文案定稿：标题「到点了」/ 正文「放下手机，去睡吧。今晚就到这里。」/ 按钮「好」。

### 3. 鼓励屏 s-done（第 7.2 条，Q6 定稿）

新增一屏，纯代码固定文案、不调模型：tag `今晚结束`、h1 `今晚这一件<br>你做到了`、voice `不用回我。睡吧，明天见。`。无返回、无按钮，只留时钟条。`localStorage.night_done_vday` 记住，刷新不丢。

### 4. 凌晨回初始页（Q5：04:00）

锁定态的有效期不是"同一个 vday"，而是**「同 vday」或「次日且时针 < 4」**——否则 23:50 接受、00:10 就被弹回首页，夜还没过完。
30s 轮询里只开**两个例外**（且都限定在锁定屏/鼓励屏上），其余屏维持"不主动切视图"的防打断原则：
1. 到睡点 → 弹睡觉弹窗；
2. 锁定态失效（vday 已变且时针 ≥ 4）→ 清状态 + 全量 `refreshState` 回 Home。

### 5. 新一天的 Home（第 9 条 + Q4）

- **回顾卡常驻**：用 `/api/state` 现成但前端一直没用的 `pending_feedback` 字段，有待回执就直接摆在 Home 上，不再等点「开始今晚」才弹；
- 答完 → **整卡消失、中间留空**，只剩问候大字 + 树洞/食记 + voice + 「开始今晚」，不出现任何"记下了"残留框；
- Home 常驻行「昨晚记为『X』点错了？改」**整行移除**（结论屏顶部那句只读显示保留）；
- **Q4：纠错入口搬进 设置 → 回看**，列表行尾加「改」，且**只有当天还能改的那条**（`/api/state.yesterday_feedback` 指向的记录）才出现；点了打开回顾卡并回到 Home；
- `offwork` 的 `need_feedback` 分支保留作兜底，未改动。

### 执行中发现并当场修掉的两个 bug

1. **重新接受会直接掉进鼓励屏**：`night_done_vday` 没在接受时清掉，第二次点「就这样」后下一次 `refreshState` 会把人送到 s-done。→ 接受时先 `removeItem(DONE_KEY)`。
2. **过期的 `accepted_vday` 赖在 localStorage 里**：锁定态失效时只是"不加锁"，没清 key；演示时把时钟拨回那一天，人会莫名其妙又掉进锁定屏/鼓励屏（实测复现）。→ `refreshState` 里发现 key 存在但已失效就地 `clearNight()`。

## 三、问题与潜在问题

1. **睡点落在零点之后（如 01:00）时，弹窗基本不会触发**。判定里对 `h < 4` 的睡点按次日算，但过了零点 vday 就变了、后端当天记录随之为空，锁定态靠"次日且 < 4 点"续着、`state.today_advice` 却已是 null，链路能撑住但没有真实数据可刷新。demo 的睡点是 22:30/23:00 这类，演示无碍；真做通宵作息要另设计。
2. **跨零点后锁定屏的建议三行来自内存里的 `currentAdvice`**，不是后端。此时若硬刷新页面，`currentAdvice` 丢失、后端当天又没有记录 → 代码会主动放弃锁定回到 Home。也就是说"刷新不丢"这条**只在同一个 vday 内成立**，00:00–04:00 之间刷新会回首页。判断是可接受的：那个时间点回首页不伤人，但要知道。
3. **锁定屏没有任何出口**（Q2 的本意）。演示时若想回去看别的屏，只能拨时钟跨天或清 localStorage。这是设计，不是 bug，但演示前要心里有数。
4. **食记在锁定屏上传后不触发重算**（Q2 明确），所以锁定屏的三行不会因为拍照而变。用户拍完只看到"记下了：xx"，可能期待建议跟着变——是既有口径，未改。
5. **睡点弹窗对同一晚只弹一次**：点「好」进鼓励屏后不再弹。若用户点了「好」又用时钟回拨到睡点之前再往前拨，因为已经在 s-done、`checkSleep` 只在 `activeScreen==='accepted'` 时工作，不会重弹。演示道具场景，未特殊处理。
6. **回顾卡常驻之后，`doOffwork` 的 `need_feedback` 分支变成了纯兜底**（跳过卡直接点「开始今晚」仍会被拦）。两条路径都会走 `openRecall`，行为一致，但代码里有两处入口，将来改回顾卡逻辑要一起看。
7. **设置→回看的「改」按钮挤在日期右边**，长句记录行里视觉偏挤（375px 下可用但不宽裕）。若嫌挤可以换成整行点击进纠错，本批按"行尾加入口"的最小改动做。
8. **`localStorage` 三个键**（`accepted_vday`、`night_done_vday`、`offworkReminder`）都是本机状态，换设备不跟随；与提醒条的既有设计一致。
9. **同构 DOM 改成事件委托后，`[data-panel]` / `[data-free-send]` / `[data-photo-*]` 这套属性成了新的内部契约**。以后再复制这块（比如第三个屏也要树洞），只要照抄 `[data-tools]` 整块即可，但不能再往里塞全局 id。
