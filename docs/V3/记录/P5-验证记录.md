# P5 验证记录：app.html 安全路径收口

> 日期：2026-08-09 ｜ 分支：ui-integration ｜ 改动文件：`frontend/app.html`（sober 映射 + crisis 整卡 + 安全出口禁用）
> 后端零改动。P4 已铺好安全五件套基础容器，本步收口触发映射与整卡行为。

## 一、改动内容

1. **sober 映射（③-9）**：`applySober(state)` 在每次 refreshState 执行——`crisis`/`danger` 或 `view=rejected` → `body[data-sober]`（整套变量覆写：灰阶、人像退方块、voice 不渲染、动效去弹性，全部由 P2 的 CSS 机制承接）；`caution` **不进 sober**（正常配色半退场）。
2. **crisis 整卡（②-5）**：只有关怀语（judgement）+ 停 + 就医行——时间带/理由行/trace 折叠全部退场；「换一种做法」隐藏（B3 口径）。内容是后端定稿文案，前端走统一渲染零特判。
3. **安全出口收口**：`.safety` 纳入 loading 禁用（P4 遗留问题 1）；行为不变——有建议 → `correct {type:"不太舒服"}`，无建议 → 进校准抽屉预置"有明显不适"（走 B2）。
4. 五件套渲染与空字段隐藏（②-1~6）、劝退屏文案用后端 message + 资料出口（②-7）、safety_level≠none 隐藏「再加一点」（②-17）均在 P4 已落，本步复核。

## 四、问题与潜在问题

1. **severe_notice 的展示位**：自由输入自述严重疾病时，当晚安全卡带 severe_notice（P4 已渲染 + toast 提示），次日起转劝退视图——链路在 B 步骤 curl 验过，本步没有再造这个状态的人眼截图（需要一次"当晚自述"的实时生成）；字段渲染逻辑与其他四件套同一条路径，风险低。
2. **sober 只挂在 app.html**：onboarding/auth/index 三页没有 sober 场景（劝退用户进 onboarding 编辑态是纠正通道，按设计保持正常配色），与原型口径一致。
3. **danger/caution 下「我要补充」仍可用**：设计如此（补充一句是安全的输入口，free_input 会再过三层检测）；只有加档和换做法按口径隐藏。
