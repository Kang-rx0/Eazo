## 一、结构与字段对齐（③-14 逐条）

六步 = 队友 ob-1~ob-5 + 新增第 6 步口味偏好（②-10 决策，s-pref 屏样式）。显示文案用队友的，**data-val 一律后端枚举**：

| 步 | 内容 | 对齐要点 |
|---|---|---|
| ob-1 | 上下班双滚轮 + 收工规律 + 通勤 | `off_work_start` 语义改为上班时间（B1 起后端即此口径）；收工规律 chips 显示"大致固定/经常比预计晚/每天说不准"、值为 几乎不加班/经常加班/偶尔加班；通勤 chips 15/30/45/60 |
| ob-2 | 白天身体状态三选 | 久坐/站着走动/体力消耗（值本就一致）；「今天有没有额外动一动」按计划删除 |
| ob-3 | 做饭方式 | 队友四选收后端三选：大多点外卖或吃食堂→只能外卖 / 几样混着来→能简单做 / 基本自己做→能正经做 |
| ob-4 | 三件套核心 | 饮食禁忌 5 chips（补回素食/不吃牛羊肉）+ 补充输入合并进 `diet_restrictions`；**病况区（③-5）**：三病名 chips 真实可选 + 自由输入，提交时合并一句存 `chronic_condition`，前端零判断零词表；病况非空展开 `doctor_advice`（②-9）；另保留 `health_note` 输入（计划未点名，但 S3 跨来源检测依赖它，删了算回退） |
| ob-5 | 安全参数 | 起床滚轮（②-11）+ 运动基础 chips（②-12，值沿用后端存量枚举 无/偶尔 等）+ 性别可选可取消（②-13）+ 年龄数字输入 + 身高体重 |
| ob-6 | 口味偏好八类 | B5 新名 data-val，可跳过（不选直接完成） |

提交后直接进 app.html，由 `/api/state` 的 view 决定显示（rejected → 劝退屏，③-6：前端不做任何医学判断）。

## 二、编辑态（②-14）

`?edit=1&sec=ob-4`（`sec=pref` 是 ob-6 别名，留给 P6 设置页）：预填 `/api/profile` 全部控件 →「存好了」升主按钮提交全量 payload → toast「存好了」→ 返回来源页。病况预填整句回显（旧格式"严重疾病："前缀剥离，沿用老页逻辑）；老账号 commute 旧档位（10/20/90）收到最近 chip；老 off_work_start 旧值（17:00 等不在上班滚轮档位内）落回默认 09:00。
**执行中发现并修正**：编辑态原来藏掉「下一步」会把不带 sec 的入口（旧 app.html「我的资料」）困在 ob-1——改为「下一步」降为幽灵按钮保留导航，「存好了」主按钮排最前；跳过链接在编辑态隐藏。旧 app.html 劝退出口同步指到 `&sec=ob-4`（一行改动，P5 换皮时会重做）。

## 五、问题与潜在问题

1. **编辑态 chips 只增不删**：病况预填时整句回显在输入框、chips 不点亮（避免保存时 chip+文本重复拼接）。用户想删掉某个病名要在输入框里删字——语义正确但和"点 chip 取消"的直觉不同。P6 设置页文案可提示"直接改这句话"。
2. **老账号旧档位有损收敛**：commute 90 分钟收到 60 chip、off_work_start 旧值（17:00 这类下班语义的存量）不在上班滚轮里、落回默认 09:00。现库存量账号均为测试号，实际影响为零；但老 demo 号如果进编辑态改资料，这两个字段会被"就近校正"，演示前留意。
3. **`health_note` 计划外保留**：计划 ob-4 清单没提它，但 V2 S3 的跨来源检测（health_note 进安全扫描）依赖此字段，删了等于安全回退，我按"硬要求不丢"原则保留。如你想收进"病况自述"一个框，需要先确认 S3 语义（两字段扫描路径不同）。
4. **浏览器面板截图右侧黑边**：面板缩放残影，DOM 度量（scrollWidth=375、按钮 20/335）证实布局正确，真机/正常浏览器无此现象。
5. **首访提交后的 rejected 显示还是旧皮**：P5 换劝退屏，本步只保证链路（已验通）。
