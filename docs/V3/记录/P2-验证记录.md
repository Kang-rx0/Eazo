## 一、nightwatch.css（全局 token + 组件库，后续页共用）

从队友原型 `nightwatch-v0.2.html` 的产品侧 CSS 整体移植，做了四类适配：

1. **评审夹具全部剥除**（①-13）：手机外壳/舞台/侧键/灵动岛/假状态栏/home 条/`@media(max-width:430px)` 去壳块，全部不进来。
2. **应用外壳重写**：`body` 即外壳——手机上全屏（100dvh），桌面收成 **430px 居中单栏**，`html` 背景同色两侧无缝；三层结构（topbar 固定 / .screens 可滚 / 每屏自带 foot）原样保留。
3. **`data-sober` 挂点迁移**：原型挂 `.device[data-sober]`，真实页面没有 .device，全部改为 `body[data-sober]`（变量覆写 + 人像退化 + voice 不渲染 + 动效去弹性，四处同步改）。
4. **预置两个原型没有的组件**（本步只定样式、P4 接线）：`.toast`（②-26，深底浅字小卡片，错误态靠文案不靠颜色）、`.clockbar`（②-25，虚拟时钟控制条，mono 小字低调角标）。

其余组件（chip/opt/btn 五态/safety/plan/srcs/rows/band/stamp/acc/field/wheel/setlist/switch/modal/抽屉外壳/recall/homegrid/homepanel/焦点/动效/矮屏降档）与原型逐字一致，`.scrim`、`.calibration-sheet` 等类名保持原型命名，方便 P3–P6 直接搬屏。

## 七、问题与潜在问题

1. **桌面 430px 上限是我的取值**：计划只说"393pt 单栏自适应铺进真实浏览器"，未定桌面表现。我取 430px 居中（≈手机逻辑宽度上限，同原型去壳断点），两侧同色无缝。如果你想要别的桌面表现（如不限宽）说一声，一行改动。
2. **已登录直通在后端未启动时静默降级**：fetch 失败留在欢迎页，无提示。属首页冷启动的合理兜底，但演示时若后端没起、点「开始认识你」登录会在 auth 页看到「连不上服务」提示——提示在 auth 层，不在 index 层。
3. **auth 页无 rejected 特判**：severe_flag 用户登录后 `/api/state` 返回 rejected view，本步按「非 onboarding 即 app.html」跳转，由 app.html 展示劝退视图——旧 app.html 已有此逻辑，P5 换皮后走新劝退屏，链路不断。
4. **`.toast`/`.clockbar` 目前是死样式**：无页面引用，P4 接线。放在本步是为了 css 文件一次成型，避免后续步骤反复动全局文件。
5. **原型的 `.status` 假状态栏剥除后**，顶部时间感由 P4 的 `.clock` 行（虚拟时间）承担，index/auth 两页无时间显示——设计如此（未登录页没有虚拟时间可显示）。
