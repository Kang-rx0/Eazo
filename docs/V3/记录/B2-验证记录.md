# B2 验证记录：/api/offwork 新增 calibration 结构化校准

> 日期：2026-08-09 ｜ 分支：ui-integration ｜ 改动文件：`backend/main.py`（两个纯函数 + `_run_and_save_today` 新参数 + `api_offwork` 接线）、`scripts/test_safety.py`（+8 单测）

## 一、改动内容（增量式，旧契约零变化）

1. **`_map_calibration(calib, remaining_min)`**（纯函数）：按计划映射表把校准翻成既有机制，不新造安全通道——
   - `body=有明显不适` → 下班状态"不太舒服"（进安全扫描 + 上下文注入的既有路径）；
   - `energy∈{几乎没有,很低}` → 下班状态"今晚更累"；body 已占用时降级为补充条件行"用户还提到今晚精力X"；
   - `time_budget_min` 比后端估算（B1 `confirm_hint.remaining_min`）更紧 → conditions 记 `剩余分钟`（宁紧不松，放宽不理）；
   - `energy=还行` 且无其他 → "今天还行"；全默认/未传 → `(None, None)`，与 `{}` 完全一致（连 conditions 都不多存）。
   - 原始校准只留契约三键原样存 `conditions["校准"]`（防前端塞杂物）。
2. **`_resolve_offwork_payload(payload, remaining_min)`**（纯函数）：`state` 合法则优先、calibration 忽略（同传防歧义）；否则走映射。
3. **`_run_and_save_today` 新参数 `calibration_conditions`**：首次生成时并入 conditions；并新增派生注入块——`剩余分钟`/`校准补充行` 存在时生成补充条件行，**与下班状态行同构：每次重生成都从 conditions 重建、继续带着**；不进安全扫描 texts（与"难度再高一点不进扫描"同一设计：非健康自述不扫）。
4. **`api_offwork`**：只在 payload 带 calibration 时才计算 `confirm_hint`（复用 B1，不额外开销）；`{}`/`{"state"}` 老分支行为逐字节不变。

## 五、问题与潜在问题（给 P4 前端与后续步骤）

1. **同传即忽略**：`state` 与 `calibration` 同传时校准整体作废（含 time_budget）。P4 前端两条路径二选一：「判断大致没错」发 `{}`、「按这个重新算」只发 calibration，别混发。
2. **时间预算宁紧不松**：用户把滚轮调得比估算更宽（如估 60 调 120）后端不放松、也不落任何痕迹。前端不要在 UI 上暗示"已按 120 分钟重新算"。
3. **睡点已过时时间校准失效**：`remaining_min=0` 时任何 time_budget 都不满足"更紧"，不会被记录。行为合理（该睡了），但 P4 的 adjust-sheet 时间滚轮默认停在 remaining_min=0 时的交互要想一下（比如隐藏时间项或直接显示"已到睡点"）。
4. **精力两档粒度合并**："几乎没有"和"很低"都映射"今晚更累"，提示词看不出差别；原始值存在 `conditions["校准"]` 里，后续若想让 agent 感知可从这取（本期不做）。
5. **校准行不进安全扫描**：设计如此（非健康自述），但意味着用户在 time_budget 里表达不了身体问题——身体问题只有 body 一条正路，P4 文案注意引导。
6. 已知未修沿用（交接文档八-6）：A1 同步 LLM 阻塞事件循环，本次 curl 串行测试无感，与 B2 无关。
