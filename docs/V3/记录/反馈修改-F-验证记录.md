> 日期：2026-08-09 ｜ 分支：ui-integration ｜ 来源：用户与队友第二轮体验反馈（三条，不在原 9 条计划内，用户当场拍板）

## 一、落地清单

### ① 删掉「身体上还有别的要注意的吗」，引导写进病况栏

队友反馈：这一栏和上面的病况栏观感重复。用户拍板：**删掉，并引导写进病况栏**。

- ob-4 移除 `#healthNote` 输入框整组；
- 病况栏改文案：标题 `有确诊的疾病吗？…` → **`身体上有什么要我知道的？常见的先点，也可以在下面自己写`**；占位 `自己的话写就行，比如：高血压五六年了` → **`确诊的病、或者要绕开的地方都行，比如：高血压五六年了 / 腰不好`**；
- **`health_note` 数据库字段保留、不迁移**：预填时接进 `prefilledHealthNote`，保存时原样写回。老账号里存着的备注继续注入提示词与 `safety.assess`，只是不再从界面收集新的。新注册用户该字段恒为 null。

**这个改动的已知代价（改之前已向用户说明，用户确认后执行）**：病况栏是自由填写、判断全在后端词表，其中有一条兜底规则（`safety.assess`，注释举例"萎缩性胃炎"）——**非空且不含严重疾病词的内容会被当成病名，按慢性病保守管理**。实测：

| 病况栏写什么 | `chronic_managed` | 派生的慢性病清单 |
|---|---|---|
| `腰不好` | **True** | `['腰不好']` |
| `胃不太好` | **True** | `['胃不太好']` |
| `膝盖以前受过伤` | **True** | `['膝盖以前受过伤']` |
| `高血压`（对照） | True | `['高血压']` |

后果是这些用户会走"四镣铐"：**档位封顶 3、运动最多散步/拉伸级、饮食清淡保守、每晚挂慢性病尾注**。

这是**既有规则、不是本次新增**（那个输入框本来就是自由填写，本来就有这条兜底），本次改动只是让它更常被触发。方向上属于"加严"，不违反安全宪法；代价是对"腰不好"这类非疾病情况**管理得过重、不够准确**。

### ② 结论屏两个折叠块合并

用户反馈：「为什么是这条线」和「它是怎么得出这个建议的」观感重复。拍板：**合成一块三行**。

| | 改前 | 改后 |
|---|---|---|
| 入口 | 两个折叠块 | **一个**：「为什么是这条线」 |
| 展开内容 | 块 1：依据 / 来源<br>块 2：trace 列表 | **依据 / 来源 / 怎么想的**（trace 列表 + 思考用时） |

- trace 套进 `.srcs` 的 `dd` 里，加三行页内 CSS 让它按无序列表排版；
- **没有 trace 时整行不出**（`#advTraceRow` 隐藏），不留一个空的「怎么想的」；
- crisis 整卡的退场逻辑跟着简化：原来要分别隐藏 `.srcs` 和 `.acc`，现在 trace 已在 `.srcs` 里，隐藏一块就同时收掉两者。

### ③ 「点下班了直接出建议」——复现失败，待用户补步骤

用户反馈：提醒条弹出后点「下班了」，直接给建议，没让选/改状态。**三种路径都没能复现**：

| 场景 | 实际结果 |
|---|---|
| 第一天 18:10 提醒条 → 点「下班了」 | → **s-confirm** |
| 生成建议 → +1d → 第二天 18:10 → 点「下班了」 | → **s-confirm** |
| 有待回执挂着时点「下班了」 | → **s-confirm** |

代码上 `remindYes` 只做三件事：记 `done`、隐藏提醒条、调 `startNight()`；而 `startNight()` 只有在 `confirm_hint` 取不到时才会跳过 s-confirm 直接生成（异常兜底），正常用户的 `/api/state` 一定带这个字段。

**一个可能的解释**：点「下班了」→ s-confirm →「判断大致没错」→ 因为有昨晚待回执，先弹回执卡 → 答完**直接出建议**。s-confirm 一闪而过，留下的印象是"回执 → 建议"。若确实如此则不是 bug。**已请用户补充复现步骤（第几天、点之前屏幕上有什么、点完直接看到什么），本条留待下一轮。**

## 三、问题与潜在问题

1. **「腰不好」会被当慢性病管理**（上面表格实测）。这是用户在知情后拍板选择的方案，方向上是加严。若之后觉得管得过重，有两条路：
   - 恢复两栏、改文案区分「确诊的疾病」与「没确诊但要绕开的地方」（本次被否的方案）；
   - 或在 `safety.assess` 的兜底规则上加白名单/长度判断——**这是安全层降级方向，必须用户明确批准**，本次未做也不建议轻动。
2. **`health_note` 成了"只读字段"**：数据库里还在、提示词和安全检测还在吃它，但界面上再也无法编辑或清除。老账号里存着的备注会一直跟着（demo1 我造的那条测试数据已还原为空）。要彻底退休这个字段得单独做一次迁移，本次没做。
3. **病况栏现在承担两种语义**：确诊疾病（触发 severe_flag 劝退 / 慢性病镣铐）和一般身体注意事项。写「以前心梗过」仍然会劝退——这是对的；但用户可能因为文案变成"身体上有什么要我知道的"而更随意地写病史，劝退触发率可能上升。
4. **trace 现在藏在「为什么是这条线」的第三行**，演示时想展示"Agent 真的调了工具"要多一次展开+滚动。若演示频繁需要它，可以考虑把「怎么想的」默认展开或换个更醒目的位置。
5. **trace 行的排版是页内三行 CSS**（`#advTraceRow dd ul`），没有进 `nightwatch.css` 的 token 体系。步骤文案很长时会折行成多行圆点，375px 下实测可读，更窄的屏没测。
6. **第 ③ 条未闭环**：复现不出来，等用户补步骤。在没弄清之前，不改 `remindYes` / `startNight` 的任何逻辑——盲改会把现在正确的行为改坏。
