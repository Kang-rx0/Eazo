## 一、落地清单

### 入口收敛为两处

| 屏 | 改前 | 改后 |
|---|---|---|
| Home | 有 | **保留** |
| s-confirm | 有 | **保留** |
| s-advice（结论屏） | 有 | **移除**（Q3 已确认不算降级：「我要补充」仍在，同一条 `/api/free_input` 管道、同样全量过三层安全检测） |
| s-accepted（印章屏） | 本来就没有 | 无 |

### 点击后弹「哪里不舒服」sheet

复用 `calibration-sheet` 样式（与「我要补充」「改一下」同一套）：标题「哪里不舒服」、说明「说一句就行，我按这个重新安排今晚。」、textarea（placeholder「比如：头有点晕 / 胃不太舒服 / 嗓子疼」）、「提交」主按钮。

### 提交链路（前端零词表、零判断）

```
/api/free_input {text}
   ├─ 当天已有建议 → 后端直接带着这句话重算，返回 {advice} → refreshState（danger/crisis 由 applySober 自动转灰卡/危机整卡）
   └─ 当天还没建议 → 存库，接着 doOffwork({state:'不太舒服'}) 生成
                        └─ 若有待收回执 → 既有的 need_feedback 分支接管，答完回执再继续生成
```

- 句子进 `free_inputs`，生成时同时喂给**【今天已知】的"用户自由输入"**和 **`safety.assess` 三层检测**——与批次 B 第 3 条是同一条管道。
- **严重程度完全由后端判定**，前端不含任何症状词表，也不预设等级。
- 空着提交 → 用 `身体不太舒服` 这一句（即按钮本身的字面意思）交给后端，不在前端加工，也不把人卡住。
- 生成分支带 `state:'不太舒服'`：保留改前 Home 那条路径（校准 `body=有明显不适` → 下班状态「不太舒服」）已有的注入与安全扫描输入，**不因为改版而少一个输入**。

### 顺带清理

`openAdjust(presetBody)` 的 `presetBody` 参数在收敛后已无调用方（原来只有安全出口传 `有明显不适`），去掉参数、身体一栏改为不预置。校准抽屉里的「有明显不适」chip 仍在，用户可手动选。

### 链路一：当天还没建议 + 有待收回执（最复杂的一条）

Home →「身体不舒服」→ 填 **「头有点晕」** → 提交：

1. ✅ `/api/free_input` 存句 → `doOffwork` 返回 `need_feedback` → **回顾卡弹出**，toast「先说说昨晚那条怎么样，说完我就开始安排」；
2. ✅ 答「做到了」后继续生成（`pendingOffworkPayload` 既有机制接管，带着 `state:'不太舒服'`）；
3. ✅ 生成结果 **`safety_level=caution`**：
   - judgement「今晚头晕、不太舒服，需优先休息」——**句子真的参与了判断**；
   - `move=null`（撤运动）；
   - eat 改成「外卖选清淡易消化的热食，如清汤面+青菜，避免油腻/辛辣/过咸」；
   - 「今晚先不：剧烈或长时间的活动」；
   - 就医行「如果不适再次出现或持续，请及时就医。」
   - caution 不进 sober（`data-sober=false`），符合 ③-9 口径。

### 链路二：当天已有建议 → 升级到 danger

Home →「身体不舒服」→ 填 **「胸口闷，喘不上气」** → 提交：

- ✅ `free_input` 直接带句重算，返回 advice，**`safety_level=danger`**；
- ✅ **`document.body[data-sober]=true`**，整屏转灰阶（截图：徽标、主按钮全部去色）；
- ✅ judgement「今晚需立即休息，暂停一切活动」；**eat 与 move 双双撤空**，只剩「22:30 放下手机、平躺休息」；
- ✅ 「今晚先不：任何运动或体力活动 / 熬夜硬撑」；就医行「如果不适持续或加重，请尽快就医。」
- ✅ toast「记下了，今晚按这个重新安排了」（不含任何"警报"式措辞，符合"语气温和不是红色警报"）。

## 三、问题与潜在问题

1. **入口收敛后，结论屏上"身体突然不舒服"要多一步**：得点「我要补充」再说，或者返回 Home/confirm 用安全出口。这是 Q3 拍板的取舍，链路与安全强度不变，但操作路径确实变长了一步。
2. **空提交会送出固定句「身体不太舒服」**。这是前端唯一一处"替用户说话"的地方——只复述按钮的字面意思，不含任何症状判断。若认为连这句都不该有，可以改成"不填就不让提交"，代价是难受的人被卡在弹窗前。
3. **`state:'不太舒服'` 与用户自己那句话会双份注入**（一条走 `conditions["下班状态"]`，一条走 `free_inputs`）。刻意保留：宁可重复，不能因为改版丢掉改前已有的输入。副作用是提示词里同一件事说两遍，模型措辞可能更强调不适。
4. **链路二会连续两次生成**的情况不存在，但**链路一在有待收回执时会先弹回顾卡**——用户点了「身体不舒服」却先被问昨晚，观感上有点绕。这是既有的 `need_feedback` 优先级（B2 牵连 5），本批没有改动它。
5. **danger 之后再点「身体不舒服」仍可继续提交**，每次都会重新生成一次。安全等级只会升不会降（当天说过的危险信号对整晚有效），但会多烧模型调用。演示时别反复点。
6. **crisis 整卡路径本批未再单独人眼验证**：`applySober` 与 crisis 渲染在 P5 已验过、回归用例 11「心理危机固定文案」这一轮仍然绿，链路是同一条（free_input → 后端判等级 → 前端照渲染），本批只换了入口。
