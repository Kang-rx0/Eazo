## 一、逐条方案

### 1. 时钟条：可加可减 + 10 分钟档 —— 前端 + 后端一小块

- 后端 `backend/main.py` `/api/clock`（约 690 行）新增 `advance_minutes` 参数：`clock.advance_hours(float(minutes)/60)` 换算即可。`timedelta` 天然支持负数；`advance_days(-1)` 可用（回到前一天 19:00）。
- 前端 `frontend/app.html` 时钟条按钮换成：`−1d −1h −10m ｜ +10m +1h +1d ｜ 重置`（紧凑 mono 标签，430px 宽度内放得下；实测挤就把 −1d/+1d 收成一组）。
- 已知边界（写进验证记录「潜在问题」即可）：回拨跨天后当天已有建议的记录还在，view 会回到那天的 advice——演示道具固有行为，不修。
- 改了 backend 必须重启 uvicorn。

### 2. 全局返回：每页可回上一步，接受后不可返回 —— 纯前端

- onboarding：ob-2~6 已有逐步返回；ob-1 按 Q9 默认维持隐藏。
- `app.html` 扩 `BACK_TO`：新增 `advice→confirm`（已有 `confirm→home`、`settings→home`、`history/about→settings`）。
  - 安全性依据：`/api/offwork` 对已生成建议短路返回 `already_generated`，从 confirm 再点「判断大致没错」瞬间回原建议，不烧模型。
  - 按 Q1：advice 已存在时，confirm 屏三处「改一下」置灰/隐藏 + 提示。
- 不可返回名单：`accepted`（锁定屏）、`bye`、`rejected`、`done`（鼓励屏）。

### 3. onboarding 问「今天经历了什么」并真实参与决策 —— 纯前端（后端管道现成）

- 照 v0.2 原型 ob-2 补回 today-only 组（`frontend/onboarding.html` s-ob-2）：
  - chips「今天有没有额外动一动」：`没有，就这样`（默认）/ `运动了一下`；
  - 一行自由输入「今天还有什么特别的（可不填）」。
  - 编辑态（`?edit=1`）整组隐藏（对齐 v0.2 `data-todayonly` 语义：这是今天的事，不是长期底子，不进 profile）。
- 参与决策机制：onboarding 提交成功后，前端把非默认答案拼成一句话（如「今天已经运动过一次；下午淋了雨」）POST `/api/free_input`。后端现成管道会把它注入当晚生成的【今天已知】并全量过三层安全检测（`main.py` 约 267 行 `get_free_inputs`）。零后端改动。
- 全空/全默认则不发请求。

### 4. 「平时吃饭主要靠什么」改四选 —— 前端 + 后端一行提示词

- 事实：后端对 cooking **无枚举校验**（`safety_regression.py` 里用着库外值「点外卖为主」也照跑）；唯一消费点是 `backend/agent.py` 约 106 行 `f"晚上{p['cooking']}"`。
- 改法：
  - `onboarding.html` s-ob-3 换四个选项，data-val 直接存自然语言：`大多点外卖` / `主要吃食堂` / `基本自己做` / `几样混着来`；
  - `agent.py` 提示词该行改为 `f"平时吃饭：{p['cooking']}"`（否则「晚上几样混着来」读着别扭）；
  - 更新 `backend/db.py` 26 行注释。
- 编辑态预填映射旧值：`只能外卖→大多点外卖`、`能简单做→几样混着来`、`能正经做→基本自己做`。demo 账号数据不迁移，靠映射兜住。
- 动了提示词 → 全量回归必跑。

### 5. 结论屏大字关键词琥珀高亮 —— 模型输出类，谨慎

- CSS 现成：`nightwatch.css` 的 `h1 em`（v0.2 同款琥珀底高亮）。
- advice JSON 契约加**可选**字段 `focus`：judgement 的原文子串、2~6 字，提示词 schema 说明里加一句（judgement/stop 必填校验 `_parse` 不动）。
- 前端渲染：`focus 存在 && judgement.includes(focus)` 才用 **DOM 拆分**包 `<em>`（严禁 innerHTML 直插模型文本）；不含或缺字段整句平铺——天然兼容 L3 强制改写后 focus 失配。
- crisis 卡 judgement 是定稿关怀语、无 focus 不受影响；sober 下 `--amber` 是灰阶，无需特判。

### 6. 「身体不舒服」收敛为两处 + 自由描述 —— 前端为主，零后端改动

- 保留位置：Home + s-confirm；**从 s-advice 的 foot 移除**（Q3 已确认不算降级）。锁定屏本无此按钮。
- 点击后弹 sheet（复用 calibration-sheet 样式）：「哪里不舒服，说一句」textarea + 提交按钮。
- 提交链路：`/api/free_input`（存句子）→ 紧接 `/api/offwork`。生成时句子进【今天已知】+ 三层安全扫描：
  - 命中 danger/crisis → sober 灰卡 / 危机整卡（即「直接回绝结束」形态，现有 `applySober` 映射自动生效）；
  - 轻微不适 → 正常降档温和建议。
  - 判断全在后端安全层，前端零词表、零判断。
- Home 上建议已存在时同样走此链路（free_input 会触发重算，danger 同样转 sober），行为一致。

### 7.1 下班询问弹窗：下班 +5 分钟首问，最多两次 —— 纯前端

- `app.html` `checkReminder`：首次出现时刻从 `off_work_end` 改为 `+5 分钟`。其余逻辑（答「还没」30 分钟后再问、最多两次、答过/自主开始即不再问=0 次）已符合要求，不动。

### 7.2 + 8 + 9 夜间闭环：锁定屏 → 睡觉弹窗 → 鼓励屏 → 凌晨回初始页 —— 纯前端状态机

**接受后锁定（含 Q2 修订）**
- 「就这样」→ s-accepted 改造成「今晚已定」锁定屏：印章 + 当晚建议 plan 三行只读；无返回、无齿轮、无 foot 按钮（时钟条保留，演示需要）。
- **保留树洞 + 食记两格入口**（复用 Home 的 homepanel/homegrid 结构）：
  - 树洞提交仍走 `/api/free_input` → 建议已存在会重算 → 锁定屏上的建议行**同步刷新**；若安全升级（danger/crisis）→ **退出锁定态**转 sober 卡（安全永远赢过锁定）；
  - 食记照片只做识别记录（现行为），不触发重算。
- 接受状态不落库（维持 ①-8 决策）：`localStorage` 记 `accepted_vday=<vday>`，刷新不丢；vday 变更即失效。

**睡觉弹窗**
- 睡点解析：`advice.stop` 正则抽 `HH:MM`（`/([01]?\d|2[0-3]):[0-5]\d/`），抽不到回落 `confirm_hint.sleep_point`。
- 30s 轮询检测 `virtual_now ≥ 睡点` 且处于锁定屏 → 弹弹窗（`.scrim`/`.modal` CSS 现成未用）。进入锁定屏时立即检测一次（接受时已过点则立刻弹）。
- 弹窗文案定稿：标题「到点了」，正文「放下手机，去睡吧。今晚就到这里。」按钮「好」。

**鼓励屏（s-done，新增屏）**
- 点「好」→ s-done。文案定稿（Q6，纯代码固定）：
  - tag：`今晚结束`
  - h1：`今晚这一件<br>你做到了`
  - voice：`不用回我。睡吧，明天见。`
- 无返回、无按钮（时钟条保留）。

**凌晨回初始页**
- 30s 轮询检测：`vday` 变化 **且** 当前时针 ≥ 4（Q5）→ 全量 `refreshState` 回 Home，清 `accepted_vday`、`currentAdvice`。
- `advance_days` 跳到次日 19:00，vday 已变且 19 ≥ 4 → 立即重置 ✓；真实时间过 00:00 时 vday 变但时针 < 4 → 等到 04:00 ✓。
- 30s 轮询「不主动切视图」的防打断原则（已知问题 #9）只开**两个明确例外**：睡点弹窗、新天重置（限锁定屏/鼓励屏上）。其余屏维持不打断。

**新一天的 Home（第 9 条）**
- 用 `/api/state` 现成但前端一直没用的 `pending_feedback` 字段，把回顾卡**常驻渲染**在 Home（v0.2 形态），不再等点「开始今晚」才弹。
- 答完 → 卡整个消失、中间留空：只剩问候大字 + 树洞/食记 + voice + 「开始今晚」。**不出现**「记下了。谢谢你告诉我。」之类的残留框。
- Home 常驻行「昨晚记为『X』点错了？改」一并移除；纠错入口按 Q4 默认搬进设置 → 回看（列表行尾加「改」入口，仅当天可改的记录显示）。
- `offwork` 的 `need_feedback` 分支保留作兜底（跳过卡直接点「开始今晚」仍会被拦，行为不变）。

## 三、硬约束（违反任何一条都算错）

1. conda 环境 `Eazo`（`/opt/miniconda3/envs/Eazo`），服务 8100 端口；改 `backend/` 必须重启 uvicorn（服务不带 --reload）；改 `frontend/` 强刷浏览器即可。
2. 只在 **ui-integration** 分支工作、只推这个分支。
3. git 提交**永不加 Co-Authored-By** 等署名尾注。
4. `.env` 只认 `LLM_API_KEY` / `LLM_BASE_URL`，不动、不进 git。
5. `backend/safety.py` 常量区定稿文案（劝退/尾注/危机）改动前必须先问用户。本计划**不涉及**这些常量。
6. 安全宪法：只能加严不能降级。第 6 条的入口收敛已由用户确认不算降级（Q3）。
7. 枚举类前后端契约（correct 类型字符串、FEEDBACK_OPTIONS 等）两端一起动；本计划中 cooking 无后端校验、focus 为可选字段，均不破坏现有契约。
