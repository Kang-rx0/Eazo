## **一、产品定义**



给每天工作很久、下班后只剩零碎时间和精力的人。不制定固定健身饮食计划，而是在下班那一刻，按当天的身体状态、饮食和剩余时间，把「今天照顾自己」缩成一组不可再缩小的行动：吃什么、动多久、几点停，并按实际完成情况调整第二天的最低线。



**追求的不是单日最优，是长期不归零。**



**与专业健康产品的分界：专业产品精确在训练内容，本产品精确在今晚的天花板在哪。** 不是更笼统，是精确的东西不同。专业产品给方案（动作清单、组数、递进、周计划），并假设用户有稳定时间和意志力；本产品只给上限加一个默认起点——「十分钟就够，饭后走走」，不成组、不计次、不递进，想换随意。运动、饮食、休息三维都只说到「多少 / 边界在哪」，不说「精确配比」。这同时是责任边界：给疲惫或不适的人开具体训练量有受伤风险，说「今晚大概能承受十分钟轻度活动」才是生活建议。



**它不是**：固定健身计划 / 减肥打卡 / 卡路里计算器 / AI 医生 / 靠连续提醒制造焦虑的产品 / 要求每天完成「完美生活」的自律系统 / 聊天机器人（能听懂话，但不对话）。



## **二、目标用户**



**优先**：工作时间长的上班族和实习生；作息不稳、加班不固定的人；想改善基本健康却难以执行固定计划的人；累了就躺着、点外卖、熬夜的人；容易「做不到完整方案就干脆全放弃」的人。



**暂不服务**：专业运动员、需严格医疗管理者、需疾病诊断者、需精确营养处方者。



## **三、设计原则**



六条，是后面所有流程决策的依据，冲突时以此裁决。

1\. **使用时刻的交互成本决定产品能不能活过第一周。** 用户在最疲惫时使用，多一步就是流失，工夫往前做。

2\. **先断言，留纠正，别先提问。** 打开是结论不是问卷。猜错的成本是一击改回来；提问的成本是让疲惫的人做决定。

3\. **一天只有一个需要用户参与的时刻。** 昨晚回执和今晚最低线在同一屏解决。

4\. **输入开放，输出形状固定。** 用户说什么都行，回应永远是那几行结论，不追问、不展开、不转成对话。

5\. **一切文案写成「避免归零」，不写「达成健康目标」。** 一出现「减脂目标」，评价标准就被拽回打卡系统。

6\. **内部状态不外露。** 「你今晚是缩减模式」读起来像降级，而本产品的核心正是把自我评判摘出循环。

## **四、用户故事**



纪律：每条以「避免归零」收尾。

|\#|故事|为了|
|---|---|---|
|US\-1|下班已耗尽，打开就看到今晚能做什么，不用先答题|不在开始前就放弃|
|US\-2|状态比平常差，一击就能让要求变小|「做不到」不滑成「全放弃」|
|US\-3|缺觉时，它敢让我别练|休息是正当结果，不是今天的失败|
|US\-4|临时加班，它知道我还没下班|不会按点收到一份四十五分钟的安排|
|US\-5|连续三天没做到，它继续缩小而非加大提醒|不因愧疚卸载|
|US\-6|只丢一句「累死了下班了」也能拿到结论|不被追问，不必组织语言|
|US\-7|第一次用，一分钟填完并当场拿到真实建议|不用等到明晚才知道它有什么用|
|US\-8|身体不适时它停下来、必要时让我看医生|不在不该动时收到训练建议|

## **五、Onboarding 字段**



**准入标准**：一个字段能进 onboarding，要满足以下之一——① **稳定 \+ 改变今晚的输出**（普通参数）；② **改变安全上限或推荐方向**（安全参数，哪怕不改变多数人的日常输出）。只满足「稳定 \+ 看起来有用」但两条都不沾的，不进。第二类是本版新增的口子，专为「极端情况下不能一视同仁」的字段（年龄、体型）留，且一律排在最后、可跳过（见「安全参数」小节）。



**全部点选、带默认、一字不打能走完；60 秒 / 5 项封顶。** 这段用户纯付出零回报，重了就到不了第一次核心体验。

### **必问（4 项）**

|字段|形式|凭什么在这儿|
|---|---|---|
|下班时间范围 \+ 加班频率|时间范围 \+ 三选一（几乎不 / 有时 / 经常）|决定介入时刻，时刻错了全盘错；加班频率决定第一天默认往哪偏|
|通勤时长|数字|把「下班了」换算成「今晚还剩多少」|
|工作日身体状态|三选一：久坐 / 站着走动 / 体力消耗|决定动作**品类**（走路 / 拉伸 / 不动）|
|晚上能否做饭|三选一：只能外卖 / 能简单做 / 能正经做|决定杠杆落在「调外卖」还是「做饭」|

身体状态必须保留「站着走动」这一档：护士、零售、教师回家时是腿废了但心肺没动，跟久坐（僵）、体力劳动（榨干）都不同，只给两档会把这群人塞错边。它掉转的是建议**方向**不是强度——同一句「饭后走八分钟」，对久坐是修复，对站了十小时是继续消耗。



### **安全闸门（2 项）**

其余字段能靠观察学到，这两样学不到且踩错有实际风险。

|字段|形式|
|---|---|
|饮食禁忌与过敏（含素食、宗教、医嘱）|多选 \+ 可跳过|
|有无需交给专业人士的健康问题|一行、可跳过、问法要轻（「有慢病 / 正在治疗的话填一下，我会调整」）|



第二项不是收集病史，是让 Agent 知道哪里该闭嘴——它同时驱动安全闸门的两层处置（严重病劝退 / 慢病适配，见六·安全闸门）。放流程最后。



### **给默认、不占一屏（1 项）**

|字段|默认|说明|
|---|---|---|
|运动基础|无 / 偶尔|往低给是有意的：起点太小可上调，太大会造成第一次失败，而本产品最怕第一次失败|



### **安全参数：身高体重 \+ 年龄（放最后、可跳过、填了作参考更好）**

\> 这三项在早期版本被列为「不问」。收入的理由不是「多点上下文让输出更丰富」——它们是静态字段，在锁死的「最低线三行」输出上，多数人身上不改变任何输出（60kg 和 90kg 的「走八分钟」是同一句），指望它们打破「输出千篇一律」是找错了头（那个瓶颈在输出端，靠自由输入、饮食偏好库、模式切换去破）。收入的**唯一正当理由是极端情况下的安全与方向**：

\- **年龄偏大**：轻度活动的强度上限确实不同，需要更温和的默认和措辞（「这个岁数别猛来，慢慢走就行」）。

\- **体型偏极端（很高 BMI）**：饮食和活动的推荐方向该不同于普通人——活动更强调关节友好（快走 / 游泳而非跳），饮食更偏「减负担」那一端。

|字段|形式|用途|
|---|---|---|
|年龄|数字、可跳过|高龄 → 收窄活动强度上限、措辞更稳|
|身高体重|数字、可跳过、不显示 BMI|仅极端区间 → 调活动方向（关节友好）与饮食减负方向|



**四条硬约束，缺一条这个字段就会变回它想避开的东西：**



1\. **放 onboarding 最后、全部可跳过。** 不填就走通用默认，一样能拿到完整首夜建议；填了作参考更好。

2\. **定性为安全参数，不是用户画像、更不是减重入口。** 不显示 BMI、不设目标体重、不做任何达成追踪。

3\. **理由行永不出现体重评判。** 年龄可以让措辞更稳，但绝不说「考虑到你偏重…」——那一句就把辛苦摘掉的自我评判又装回循环里。体型只在后台影响方向，不在台面上被点名。

4\. **只在极端区间生效。** 绝大多数目标用户（上班族、实习生，多在正常区间）填了也不改变输出，这是对的——它是安全兜底，不是日常引擎。



### **不问**



\- **职业标签。** 已被「工作日身体状态」替代——要的是这份工作对身体做了什么，不是它叫什么。

\- **目标体重 / 健康目标。** 一让用户填目标，评价标准就被拽回打卡系统。



### **两条结构性规则**



\- **硬约束 vs 参数。** 饮食禁忌与健康边界是硬约束，任何情况不被覆盖，纠正入口和自由输入都不能突破；其余字段是参数，可被当天纠正平移、随时间修正。不分层，工程侧容易把过敏和「今晚更累」放同一层处理。

\- **能砍就砍的只有两项**：运动基础（有默认）和晚上能否做饭（可默认「只能外卖」，那本就是多数目标用户的情况）。

## **六、功能流程**



\> 整体生命周期见**流程图 · 图一（主流程）**：首装 → 首夜建议 → 每日循环（触点 → 写数据 → 次日调整）。

### **F1 首次进入**



字段顺序：作息范围\+加班频率 → 通勤时长 → 身体状态 → 能否做饭 → 饮食禁忌 → 健康边界（可跳过）→ 年龄 / 身高体重（安全参数，可跳过）→ **立刻给一次首夜建议**。安全参数排在最后、可跳过，是为了保住「一字不打也能走完、当场拿到建议」——跳过它不影响任何一步。



最后一步是关键：用户第一次打开很可能本来就是晚上、本来就累，让他等到明晚才见价值，是白扔掉唯一一次最有动力的时刻。



**首夜起点定在「正常模式的下沿」——不是地板，不是理想量。** 给地板等于一上来假设他会失败、也显得没料；给理想量（F4 的天花板）会造成第一次失败；下沿则完成概率极高，又不至于简单到让人觉得「不需要 Agent」。落屏：方向由身体状态定（久坐→走动修复 / 站着走动→拉伸垫腿 / 体力消耗→纯休息），量取最小可见档（走 8 分钟不是 15），停锚在「比平时早一点点」，**理由行必须回显 onboarding 字段**（「按你久坐\+通勤 40 分钟算……」）——首夜是唯一一次建信任的机会。



注：首夜是动力最强的时刻，理论上能给高点，仍压低——首夜失败的代价大于惊艳的收益，而惊艳靠理由行让适配可见就能拿到。



### **F2 每日触点（唯一需要用户参与的时刻）**



\> 决策全貌见**流程图 · 图二（每日触点决策）**。

**推送时机：下班范围早端、人还在通勤路上，不是到家时。** 外卖决定通常在路上做，进门才推，「吃什么」这个对疲惫用户最有效、成本几乎为零的杠杆就废了。onboarding 两个数字正好够算：下班时间发推送，加通勤算到家时间。

**第一行是确认不是结论：「下班了吗？」**

\- 「还在忙」→ 整件事往后挪，不留未完成感。**最多顺延两次，之后彻底沉默**，界面留着随时可看。绝不每半小时问一次。

- 「下班了」→ 出结论。

**「还在忙」是最有价值的输入，不是噪声。** 它一次说明三件事：时间更少、精力更低、归零风险更高，用户点这一下就把状态确认做了大半；也是最好的学习信号（这人只要干到九点后就全线归零）。实现上当正式条件输入，别当推送校准的技术细节。



**结论屏（最多四行，任一维可缺席）**



```Plain Text
今晚判断 + 理由    例：今晚只剩 20 分钟左右，不安排训练
吃什么             例：想吃火锅就吃，点清汤锅、涮菜多一点
动多久             例：饭后走八到十分钟
几点停             例：23:00 放下手机
```



\- **任一维可缺席**：哪维今晚没有该说的就不出现，绝不为填满版式硬凑。饮食尤其常缺席（已吃、在公司吃、今晚想好好吃），详见 F2\.1。

\- **理由行刻意保留**：零交互成本，让「适配」变得可见，也充当自由输入的回执（证明听懂了），不必为「确认听懂」单独设计 UI。

\- **零输入是合法默认路径**：读这几行、一次不点、直接执行。



**三种输入回路**（都汇回模式判定，重出结论）：



1\. **一击纠正**（粗颗粒、点完即重出、不追问）：今晚更累 / 时间更少 / 不太舒服 / 今天还行 / 其实我做了。每个直接平移内部模式，由用户按需触发，不是 Agent 主动伸手。

2\. **自由输入（打字必做，语音加分）**：打字承载核心时间窗（通勤常不能说话）和核心演示那帧，不可降级；语音能做就做、做不完只留打字、不当排期卡点。价值在装按钮装不下的东西（「加了三小时班」「明天早会」「胃不舒服」「今天走了两万步」）。界面上是个小入口（麦克风 /「补充一句」），**不做第一屏主角**——空白输入框加疲惫用户，等于把「我该说点什么」又推回去。

3\. **安全信号**（唯一能打断正常流程的东西）：「累」不是，「疼 / 晕 / 胸口不适 / 喘不上气」是。听到后者不照常给建议，确认一句后走恢复优先、必要时提示就医，不做疾病判断。



**信息不全不提问，直接给结论。** 判据：只有缺失变量会**翻转模式**（而非微调内容）时才允许问，上限一次，两选一点选，绝不开放式问句。比提问更省的替代是**把猜的前提写进理由行**（「按你通勤 40 分钟算，到家约九点四十，所以今晚不安排训练」），用户不是这样自己看见会改，等于问了但不占他精力。



**兜底**：语音识别失败或输入无法用（只说了「嗯」），回落零输入默认路径，不因没听懂转成盘问。



### **F2\.1 「吃什么」这一维：从加法补丁翻成负担管理**



单列，因为它最容易做坏——做不好就是每晚一句「加份蛋白质和蔬菜」，既呆，又是全产品最像 if\-else、最经不起「拿掉 AI 还成不成立」那一问的地方。



**病根是方向反了。** 运动和休息的默认是「做一点点 / 停下来」（往下减），饮食的默认却被写成「加一样健康的」（往上加），而「加蔬菜蛋白质」就是这个「加一样」的最大公约数——不随状态变，因为压根不由当晚状态驱动。更深一层它违背灵魂：产品讲「要得更少」，每晚多加一样菜是「要得更多」，对累瘫的人是负担。



**换一根轴：不是「今晚加什么健康的」，而是「这顿什么形状、要不要将就、能不能只挪走最伤的那一口」。** 更多是减、撤、允许：



- 太晚 / 太累 → 降这顿的要求：「太晚了别吃正经饭，垫一口，别空腹睡也别撑着睡。」

- 已经吃了 / 在外面吃了 → 这一维不出现。

- 想放纵 → 允许，只挪最伤的一个：「想吃就吃，把配的奶茶换成一杯水，明天没事。」不否定、不说教。

- 胃不舒服 → 转清淡、少量、热的。

- 只有状态还行 \+ 能做饭时，才轮到「下碗面丢把青菜」这种真加法。

分界仍守得住：只说到分量、时机、要不要将就，不碰卡路里和精确配比。改的不是让它更精确，是让它更会「减」和「撤」。



**饮食偏好库（用户后续自设，不进 onboarding）**：从 6\-8 类「常吃形态」勾选，每类挂一组「怎么少受伤」的轻推轴。

|类别|轻推方向（示例，非硬规则）|
|---|---|
|粉面类（螺蛳粉、拌粉、汤面）|少主食多配菜、汤别喝完 —— **螺蛳粉少粉多菜**|
|炸物快餐（炸鸡、汉堡、薯条） |去皮、别配含糖饮料 —— **炸鸡少吃点皮**|
|盖饭 / 便当 / 米饭类|调菜和饭的比例 |
|火锅 / 麻辣烫 / 串|清汤、多涮青菜、蘸料别厚|
|烧烤 / 夜宵|挪时机、控分量|
|甜品 / 奶茶 / 饮料|减糖 / 换无糖 / 当加餐别当正餐|
|轻食 / 沙拉|提醒别只有菜没蛋白|
|自己做的家常|给最轻的加法|

粒度定在「形态」层是刻意的：菜系太粗挂不上轴，单品太细装不下人。这库也是「拿掉 AI 不成立」的实证——用户随口报一个没预设过的食物（「今晚想吃黄焖鸡」），靠 AI 即时生成「少要点米饭、多加个青菜」，规则表穷举不完。设置沿用点选、带默认、可跳过、后续自设。



**两条硬纪律**：

1\. **没说今晚吃什么时不硬猜、这一维缺席。** 猜错食物比不说更让人觉得「不懂我」；用户自由输入说了才即时微调。

2\. **状态越差，越往「允许」收，微调只在状态还行时出现。** 守住它是「允许 \+ 轻推」（「想吃就吃，顺手少放点粉，明天没事」），不是「你又吃炸鸡？记得去皮」。状态差的晚上「想吃啥吃啥，别空腹睡」就够了。

任何微调不突破饮食禁忌（硬约束压参数）。



**用户主动上传三餐（欢迎，但从不要求）。** 「克制」约束的是我们主动伸手的次数（推送、提醒、追问），不是用户主动给的东西。用户愿意随手报一下 / 拍一下今天吃了什么，我们照单全收，并让当天的饮食建议相应变化——这和「还在忙」一击、自由输入随口一句是同一个模型（我们不问，你给我就接住），是「克制」的正确用法，不是破例。它同时补强了饮食维的差异化，且靠的是真实输入，不是加静态字段。



三条硬约束，缺一条它就会长成打卡功能：



1\. **永远可选，永不催促。** 不做成首屏功能、不做成「三餐打卡卡片」，收进已有的自由输入小入口（想说就说、想拍就拍）。**绝不因为用户「没传」而 ping 他**——一旦开始催「你今天还没上传」，就破了克制。「没传」不等于「没吃」。

2\. **只往前看，不评判已经吃的。** 措辞永远是「根据你今天已经吃的情况，晚饭建议 xxx」——已经吃下去的只当**输入**，不当**评分对象**。绝不出现「你中午热量有点高」「你又吃炸的了」这类回头评判，那会撞上饮食维红线，也会让人再不敢传。看到什么都不说教，只顺势安排后面那顿的「负担」，允许优先。

3\. **上传内容按「用户自报」存**（见第七节），与系统推断分字段，别把没传当没吃。



### **F3 停下提示（提示，不是触点）**



「几点停」是个未来时刻，到点提不提醒两边都有代价：不提醒，这条建议基本等于没有（它要生效的时刻正是用户最不会主动开 App 的时刻）；提醒了，有滑成健康焦虑的风险。



结论：**本期做**，但与 F2 严格区分——F2 是**触点**（要注意力、可能要决定），F3 只是**提示**（一句话、不要回应、不追问、不记失败、无视即无视）。一天仍只有一个需要用户参与的时刻，不写清这区分，工程会把它做成打卡闹钟。



F3 同时是最低线缩到底后的兜底（见 F4）：缩无可缩时，输出退化成这一句「少玩手机、早点睡」。它不是独立功能，是最低线的地板本身。



### **F4 次日调整**



\> 模式与最低线的升降见**流程图 · 图三（模式状态机）**。

读昨晚记录（含沉默与默认）→ 连续未完成则继续缩小 → 状态好可小幅上调，但**上调有天花板**。



**上调不超过「理想量」，且理想量不外露。** 这是和普通 App 最反直觉的一处。普通 App 把计划当**必须完成的地板**（定了 30 分钟，做不到就是欠账）；本产品把同一个数字翻过来当**天花板**——那是状态最好时最理想的样子，日常最低线在它下面浮动，只能贴近不能越过。「最低线膨胀成另一套严格计划」这条风险被它从机制上堵死。天花板两个来源：



1\. **默认（多数人走这条）**：系统按身体状态 \+ 剩余时间隐性推算，不叫「目标」、不摆出来、不显示成进度条，只在上调时当封顶。用户不特意设就永不主动提它——既落地机制，又不违反「不让用户填目标」。

2\. **例外**：用户自由输入自己说出理想量（「其实我想恢复到每天跑三公里」），就用他的版本覆盖。设了就尊重。



**缩小有下限。** 缩到「提前二十分钟放下手机」后不再往运动 / 饮食缩，收敛到一句睡眠底线「少玩手机、早点睡」（即 F3），**不安静、不消失**。最低谷时产品彻底沉默会被读成「放弃我了 / 坏了」，保住这一句是持续在场的承诺；写成「安静几天」则会在用户最需要陪伴时断掉。



### **安全闸门（横跨全部流程）**



**红线（总纲）：绝不提供任何专业医疗建议。** 下面所有安全动作都从这一句推出来，不是并列的新规则。任何时候当「照顾用户」和「不越界行医」冲突，一律退到「别逞能、请听专业的」那一边。



基础闸门：饮食禁忌与健康边界是硬约束，任何纠正和自由输入都不能突破。出现疼 / 晕 / 不适类信号走恢复优先、必要时提示就医，**不做疾病判断、不继续给训练建议**。



**信息来源**：靠 onboarding 安全闸门那项「有无需交给专业人士的健康问题」触发。它仍**可跳过**，只在那一步加一句轻提示（「有慢病 / 正在治疗的话填一下，我会调整」），**不强制**；没填就走通用默认。



#### **第一层 · 严重疾病劝退**



内置一份硬编码的病种清单——这些情况的饮食与运动**必须由专业医疗管理**，任何「最低线建议」都可能有害。命中则**不服务**：明确、温和地建议不要依赖本 agent，去找专业人士，而不是硬塞一份最低线。



劝退判据\(命中任一即劝退\)

- R1 饮食是治疗的核心、必须精确处方,通用"吃什么"建议会干扰治疗甚至有害

- R2 运动有明确禁忌或需专业监护,"随便动动"可能出事

- R3 对食物 / 身体 / 控制的任何暗示都可能触发或加重疾病\(进食障碍专属\)

- R4 特殊生理状态,身体规则和常人不同,通用建议不适用

- R5 处于急性 / 不稳定期,不是"日常自我照顾"能覆盖的

#### **第二层 · 慢性病适配（本期挑 1\-2 个常见的做样例）**



命中慢病**不劝退**，但改策略。**本质不是「我更懂这个病」，而是「我知道自己不该在这儿逞能，所以退一步、并提醒你听专业的」**——这和产品「只给程度不给计划」的分界一脉相承。



能做 / 绝不做，是红线的直接展开：



\- **能做**：整体降调（更温和的活动、通用安全常识如「别空腹剧烈运动」）；每次建议挂一句「以你医生 / 营养师的方案为准」；饮食维彻底退到「允许 \+ 不评判」。

\- **绝不做**：算碳水 / 报升糖指数 / 报盐分数字、说「你应该吃 X 不吃 Y」、任何可被理解为治疗方案或疾病管理指令的东西。

本期两个样例：

|慢病|策略（都不碰具体医疗数字）|
|---|---|
|糖尿病|活动更温和、不建议空腹运动；饮食只「允许 \+ 别评判」，绝不碰血糖 / 碳水相关数字；挂「以你的诊疗方案为准」|
|高血压|活动别剧烈；通用方向「口味别太重」点到为止，不报盐分数字、不开食谱；挂「以你的诊疗方案为准」|

## **七、数据记录与学习口子**



学习模块本期不做，但**写数据那一端必须第一天上线**，否则三个月后历史里全是不能用的记录。



**记什么——条件与结果绑在同一条记录里**（关键不是完成率）：



```Plain Text
到家 21:40 / 精力低 / 剩 20 分钟 / 久坐型 / 缩减模式
建议：饭后走八分钟   结果：只完成一部分
```



这样将来才问得出真正有价值的问题：不是「这人完成率多少」，而是\*\*「这人在什么条件下会崩」\*\*（例如到家晚于 21:30 就全线归零，与自报精力无关）。条件不记，这个问题永远做不出来。



**反馈四档**：完成了 / 只完成一部分 / 完全没完成 / 建议仍然太难。最后一档信息量最大（用户主动给的负反馈，比推断可靠），不能省，但**绝不主动问**，常驻可点、自愿触发。四档是上限，不为数据好看而加重反馈。



**默认与推断必须与用户自报分开存。** 不问「你为什么没做到」（所有习惯类产品都问、也最伤人，问一次就把自责循环装回去了），行为上默认往「今天状态不行」理解并缩小。但**默认可以决定「怎么反应」，不能决定「往记录里写什么原因」**：把没做到直接写成「太累了」，等于把推断当事实，三个月后分不出哪些是用户真说的、哪些是系统填的——而状态问题该临时缩小、标定问题（这条建议对他本就太难）该永久调低基线，短期一样长期不同。故分三种来源存，行为可一样、字段必须分开：① 用户明确报的 ② 从沉默推断的 ③ 系统默认填的。用户主动上传的三餐（见 F2\.1）归入第 ① 类「明确报的」，是很强的条件数据——将来能看出「这人一到晚上就报复性点炸鸡」这类模式；但同样守这条纪律，**「没传」记为缺失，绝不推断成「没吃」**。



**沉默也是数据。** 最典型的一晚是连 App 都没打开——那不是缺失值，是最强信号。记「已送达、未响应」，不重复推、不加大提醒，次日最低线自动更小。



**反向不对称：别把成功记成失败。** 默认「没做到」意味着真做到的人必须主动说，否则数据把成功记成失败、一路缩到零。所以纠正入口里最该显眼的一个是「其实我做了」，一击，别藏。



**冷启动**：历史不足（如少于 5 次）一律走内置默认动作 \+ 首夜起点；从第 N 次起才允许 F4 上调并受天花板封顶。这条写清，学习模块没做完也不影响主流程跑通。



**默认动作从哪来**：本期取前两条，第三条留口子——① onboarding 让用户填两三个「我愿意做的事」 ② 内置一小组通用默认（走路、拉伸、把腿垫高）③ 从实际完成过的动作里学（长期最强，但本期没历史数据）。



## **八、已拍定的决定**



留存结论供组内对齐、防翻案。均已落进对应章节。



1\. **F3 停下提示：本期做。** 严守「提示不是触点」，同时是缩到底后的兜底（详见 F3）。

2\. **自动判断离开工位：本期不做，但作为明确规划保留、可对外宣传。** 地理围栏 / 离开 WiFi / 运动状态是零输入终局解，但要常驻定位权限、onboarding 转化率代价大；本期用「定时猜 \+『下班了吗』一击确认」顶上。**关键动作：从第一天起记真实到家时间**，将来上定位才有历史可对齐。对外讲成「下一步」而非缺失。

3\. **缩到底：保睡眠底线，不安静**（详见 F4）。

4\. **上调不超过隐性「理想量」天花板，默认不外露；用户主动说了才用他的**（详见 F4）。

5\. **自由输入：本期做，打字必做、语音加分**（详见 F2）。

6\. **首夜起点：正常模式下沿**，理由行回显 onboarding 字段（详见 F1）。

7\. **收入年龄 \+ 身高体重，作为安全参数放最后、可跳过**（组会新增）。诉求源于「高龄需特别关照、极端体型的饮食活动方向该不同」。定性为安全参数而非用户画像：不显示 BMI、不设目标体重、理由行不出现体重评判、只在极端区间生效。**须同步认清**：它不解决组会提的「输出千篇一律」——那个瓶颈在输出端（三行最低线），靠自由输入 / 饮食偏好库 / 模式切换去破，不靠加静态字段（详见 F1、安全参数小节）。

8\. **用户可主动上传三餐，欢迎但从不要求**（详见 F2\.1）。属「克制」的正确用法（约束的是我们主动伸手，不是用户主动给）：永远可选、绝不因「没传」催促、只往前看不评判已吃的、按用户自报存。

9\. **红线：绝不提供任何专业医疗建议**（详见六·安全闸门）。两层处置——严重病硬编码清单命中即劝退不服务；慢病（本期样例糖尿病 \+ 高血压）不劝退但只降调 \+ 挂「以诊疗方案为准」，不碰任何医疗数字或治疗指令。病种清单为占位、待医学 review。

|风险|对策|
|---|---|
|做成泛化 AI 健康助手|只答三个问题、只在一个时刻介入、只给程度不给计划|
|身高体重把产品拽成减重工具 / 装回自我评判|放最后、可跳过、定性为安全参数；不显示 BMI、不设目标体重；理由行不出现体重评判；只在极端区间生效|

|越界给出专业医疗建议（安全 \+ 合规风险）|红线总纲「绝不提供专业医疗建议」；严重病命中即劝退不服务；慢病只降调 \+ 挂「以诊疗方案为准」，绝不碰血糖 / 碳水 / 盐分数字或治疗指令；病种清单标「待医学 review」不假装权威|

|输入太多，用户不长期用|零输入默认路径 \+ 一击纠正 \+ 一天一触点|
|建议太简单，觉得不需要 Agent|理由行让适配可见；自由输入承接按钮装不下的条件；演示放在「主动要得更少」|
|饮食维坍缩成「每晚加蔬菜蛋白质」|换轴到「负担管理」（减 / 撤 / 允许）；结论屏行数可变、这维常缺席；偏好库 \+ 开放域食物即时微调；状态越差越只「允许」|
|健康边界失守|硬约束不可覆盖；只给程度不给训练量；不适时停止并提示就医|

|默认「没做到」污染数据|三种来源分字段存；「其实我做了」显眼|
|须证明持续适配比固定计划更能改变行为|本期靠演示 \+ 定性反馈；学习模块留口子|



## **十、核心演示建议**



评分权重：洞察 30% \+ 创意与体验 40% \+ 真实使用 20% \+ 技术 10%。70% 押在洞察与机制，演示要证明的不是模型多强，而是**机制不可被穷举**。



**最该演的一帧**：用户丢一句乱话（「今天加了三个小时班累死了」），Agent 从里面接住一个他自己都没意识到提供了的条件，然后**主动把运动整条撤掉**，只留一句吃什么和几点睡。（对应流程图 · 图二的 \`自由输入 → 模式判定 → 结论屏\` 这条线。）



两个要点：① 演「加班不定」这个场景，不要演三段干净的脚本化递减——那看起来就是一棵决策树；② Agent **主动放弃要求**的那一刻，是任何固定计划产品都模仿不了的。
